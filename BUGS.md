# BUGS.md — audit of `bugfix/audit-2026-09-29`

Audit date: 2026-09-29. Base commit: `b61e39fb` (main). Method: 8 read-only area audits (gateway ×2, auth, billing, accounts, data, frontend ×2),
then every finding was independently re-checked by adversarial verifiers (two independent verifiers for Critical/High, one for Medium/Low).
A bug is **Confirmed** when the verifier traced the full code path end to end; every fixed bug additionally has a regression test that failed before the fix and passes after it.

Severity is the post-triage severity (verifiers downgraded several reports; see notes). Severity overrides: D-01 kept at Critical
(verifiers said High) because one ordinary API key can disable the entire upstream pool with ~1 request per 11 accounts.

Duplicates merged: E-01 → D-02, E-04 → A2-04, C-06 → B-03 (same root cause).

- **A1-03** — Per-request-priced channels: a stream whose very first upstream event is `event: error` used to be recorded as a zero-token success (and charged the per-request fee); it now fails over like /v1/messages. Token billing is unchanged in every case.
- **A1-05** — The bridge idle timeout uses the existing `gateway.stream_data_interval_timeout` (default 180s); on timeout the stream is finalized exactly like an upstream read error today (see A1-04, left for approval).
- **A1-10** — In-stream `event: error` now maps to 529/429/500/400/401 by `error.type` instead of always 403. Admin error-passthrough rules keyed on 403 for these stream errors would no longer match.
- **A2-05** — Admin GET of image-storage settings now surfaces a DB read error instead of silently showing config.yaml values.
- **B-01** — A user with TOTP enabled can no longer attach a *new* Google/GitHub identity via email-match auto-login; they get the existing OAuth error redirect (`OAUTH_TOTP_BIND_REQUIRED`) and must sign in with password + 2FA. Already-bound identities and non-TOTP users are unaffected.
- **C-01** — Unknown `order_type` values now get 400 `INVALID_ORDER_TYPE` (the frontend only ever sends balance/subscription).
- **C-02** — Recharge min/max are now checked in the gateway currency after USD conversion; an out-of-range amount is rejected after the cancel-rate-limit / user-status checks instead of before them.
- **D-03** — Clearing an error (recover state / re-auth / clear error) now also restores `schedulable=true`, but only for rows still in `status=error`; manually paused active accounts stay paused.
- **D-06** — Adds a per-account one-shot timer that rebuilds scheduler buckets ~1s after a rate-limit/overload/temp-unsched block ends.
- **E-02** — The scheduler outbox watermark can now trail by up to 5s at an id gap (events after the gap are still handled immediately, exactly once per instance).
- **F1-02** — 'Bulk edit filtered' now loads all matching accounts (lite, 1000/page) instead of the first 100 to derive platforms/types.
- **F1-08** — Logging out from Settings with unsaved changes no longer prompts (the edits could not be saved after logout anyway).
- **F2-02** — Pending-payment snapshots written before this change (no owner) are discarded once the user id is known.
- **F2-10** — After a password change the user is signed out and sent to /login. The 8-char minimum in the profile form (backend/register allow 6) was left alone — policy decision for you.
