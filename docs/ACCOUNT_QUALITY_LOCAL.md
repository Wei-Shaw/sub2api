# 分组账号质量管理与自动调度

更新：2026-10-19。工作分支：`codex/account-group-quality`。

## 使用入口

本机地址：`http://127.0.0.1:8080/admin/accounts`。运行目录 `C:\sub2api-local`，启动脚本 `start-all.ps1`。远程服务器未更新。

账号管理默认按分组卡片展示，支持搜索、平台/状态筛选、卡片折叠、每组独立分页与组内排序。未分组账号单列；账号同时属于多组时分别展示。同一账号跨组勾选只计一次，批量操作复用原有管理逻辑。右上角可返回原始列表使用原有完整列与筛选。

## 账号调度与容量

分组卡片增加“容量”和“调度”列，调度开关调用原账号列表的同一接口。关闭后该账号停止接收新调度，已建立请求继续按原有网关行为处理；这是账号整体状态，会同步到该账号所属的全部分组。保存期间同一账号在各卡片的开关一起禁用，失败保留原状态；成功后刷新相关分组的可用账号数、排名及份额，并同步原始列表。

容量复用原列表的显示组件，展示当前并发/并发上限，以及已配置的API Key额度、Anthropic窗口费用、会话数和RPM限制。数据按当前页账号批量查询，容量响应不包含账号凭据。读取失败保留未知值，显示“—”；可用页面刷新按钮更新运行时容量。

## 巡检设置

每组的“巡检设置”分别保存：

- 请求模型、推理程度、服务档位和接口协议；使用请求模型名，账号映射仍由现有上游适配器处理。
- 默认每 15 分钟巡检，允许 5–1440 分钟；最多两个账号同时测试，轮次不重叠。
- 每日请求次数上限、每轮账号上限。预算单位是请求数，不是美元；检测消耗上游模型额度。
- 可选的 ModelTrace 异常复核、短/中/长合成上下文检查。
- 质量/首字/缓存/稳定性四个评分权重，默认 40/25/15/20。
- 调度模式：手动、仅观察、自动质量加权。自动调度与付费巡检使用独立开关。

新组的自动巡检和自动质量调度默认不开启；显式设置模型后才允许巡检或自动模式。验收保留用户已经保存的分组模型、手动检测历史和账号数据。

接口选择：OpenAI Responses、OpenAI Chat Completions、Anthropic Messages、Gemini generateContent。API Key 账号可以显式选择其供应商兼容的接口；OAuth 账号使用其原生平台适配。原生 Gemini 检测当前要求 `unspecified` 推理程度与默认服务档位，以免声称发送了未实现的参数。供应商或模型不支持某个参数时显示技术异常，不将其算为题目答错。

## 检测流程与防伪造证据

常规巡检以固定糖果题为主，提示明确禁止联网搜索、调用命令、历史记忆和代码文件。固定题表格为圆形 7/9/8、五角星形 7/6/4（苹果/桃子/西瓜），唯一通过答案为 `21`；`28`、`29`、`31` 等其他数值均判错。严格解析最终答案，不能因为回答中偶然出现 `21` 就通过。标准答案仅用于本地判分，不发送给受测账号。首次答错追加最多两次确认复测；网络、鉴权、余额、限流、超时、响应不完整与答案错误分别记录。通过后追加随机糖果变式，变化实际数量和标准答案；标准答案由形状配额穷举算法计算，并有独立的口味抽样穷举测试校验。

随机题或上下文检查失败会标为结果不一致/待复核，不因为固定题通过而隐藏异常。测试始终锁定账号，不能切到其他账号后给原账号记通过；质量探针不会沿用连通测试中的 401/429 禁用/限流写入。

ModelTrace 完全本地运行，随程序嵌入参考库、Go 算法与 MIT 许可，保存库 SHA-256、预期参考模型、三个挑战及回答、首位候选与相对支持度。三份有效输出才做完整归因，缺失或无法解析保持 unknown。0.8 的候选判定线是本地保守显示规则，未被宣传为身份认证；不在参考库的模型不能指定为参考。

上下文检查使用随机生成的合成记录，分别测试约 1K 字符、中等长度和配置的长长度（4K–128K 字符），由程序保存标准答案。测试不使用或上传真实用户内容。

每份新结果保存题库版本、协议/模型/推理/档位、回答、题面与回答摘要、总耗时和请求次数。回答摘要只帮助核对本机归档一致性，不能证明上游身份。历史生成内容只以文本展示，不执行模型返回的 HTML 或代码。

同条件账号跨组的近期固定题可以在定时巡检中复用 15 分钟，复用记录不增加独立样本、不能链式延长有效期。手动重测始终产生新的测试请求。

## 真实业务指标与评分

- 性能窗口为最近 24 小时，按分组、账号、请求模型、推理程度、服务档位、协议分别统计。未配置模型时展示全模型概况，不能将它作为跨模型公平能力比较。
- 首字使用网关已有 `first_token_ms`，展示 P50/P95。评分兼顾中位数与尾部延迟，至少 30 个有效样本才参与。历史不同透传路径的计时语义不完全相同，不能当作供应商身份认证。
- 缓存使用归一化后的 `cache_read/(input+cache_create+cache_read)`，为 token 读取占比，不是命中请求比例；仍依赖上游报告的 usage。
- 稳定性使用已记录的成功用量与去重错误，排除业务限制、客户端错误及同账号最终成功的重复错误。错误日志关闭或档位/协议覆盖不明时不推断为完美稳定。
- 新增错误条件字段只保存推理程度和服务档位，不恢复已删除的错误请求体列。历史错误缺少条件时明确降低覆盖可信度。
- 能力题使用最近 1 小时独立固定题结果，至少 3 个有效结果才参与。指纹证据独立展示，不把候选支持度当“智商”。
- 缺失项不记零分；点击评分可查看分量、样本数、基础权重与有效归一化权重。
- 建议份额包含待评估账号的中性探索份额，不等于实际路由百分比。

## 实际自动调度

自动模式按分组 + 请求模型 + 推理程度 + 服务档位 + 接口精确匹配。推理程度未明确传递时，只匹配 `unspecified`。非匹配请求继续原有调度；图片/压缩等其他接口不会被误当成普通文本接口。

采用原子快照供请求热路径读取，缺失或超过两分钟未更新时回退原生调度。质量乘数与现有候选、负载、排队及准入规则组合，每分钟最多变化 0.15，限制在 0.1–2；未知账号从中性值开始。候选内保留 5% 均匀探索份额。OpenAI 新调度与通用/旧调度均有接入，不会只改变列表排序。

健康会话继续粘连，已确认的近期能力异常可逃逸普通会话粘连；不能移动的 previous_response/tool/guardian 绑定继续保护上下文一致性。并发、额度、模型能力、分组限制等仍由原有准入代码执行，不覆盖账号全局优先级。关闭自动模式会清除本机该组的质量快照，其他节点在其刷新周期内退出。

“调度诊断”显示条件匹配结果、生效乘数和近期选取记录。事件是本节点内存记录（最多 512 条，显示最新 100 条），重启清空；不是永久审计库，也不等于完整调用链。

## 预算、恢复与部署

每轮按最坏情况先原子预留：糖果最多 3 次、指纹 3 次、上下文 3 次；常规轮启用附加复核时最多预留 9 次/账号。完成轮次按已消耗请求释放剩余预留，异常取消轮次保守保留预留。按北京时间日界线计算预算，跨午夜旧轮次停止，避免占用新一天未预留额度。预算不足暂停到次日；账号上限按最久未测优先轮换。

数据库租约防止跨进程重复轮次；过期轮次标为 interrupted，取消/过期任务无法继续写入或复活。重启后重新加载策略、参考库和渐进乘数，不重放已完成题目；未完成轮次保留异常状态供查看。

数据库迁移：246 新增策略/任务/结果表；247 新增指纹证据、协议、请求计数和独立组内权重表；248 新增错误条件字段。原始账号凭据、余额与全局优先级不变。

备份：

- 第一阶段前：`C:\sub2api-local\backups\before-account-quality.dump` 与 `sub2api-before-quality.exe`。
- 完整版前：`C:\sub2api-local\backups\before-quality-complete-20261019.dump` 与 `sub2api-before-quality-complete-20261019.exe`。
- 恢复旧程序可忽略新增独立表；不要随意回滚数据库覆盖后来用户产生的记录。

## 验收证据

- 前端 8 个组件行为测试与 3 个语言键测试，类型检查、ESLint、Vite 构建。
- 后端严格判分、随机题标准答案、上下文记录、预算/跨日边界、十五分钟调度、单账号锁定复测、技术异常分类、多协议模拟传输、评分/平滑权重、跨条件隔离、探索采样、完整 OpenAI 调度、手动模式回退和错误条件字段测试。
- ModelTrace 原项目固定样本的概率/排名/相似度对照验证，参考库摘要校验与无效样本测试。
- 本机 PostgreSQL 私有 schema + 仅 loopback 模拟上游，执行真实糖果、变式、三次指纹、短/中/长上下文、取消及预算进度；结束后清理私有 schema，不读写 public 账号数据。
- 实际运行 API 核验分组、分页、历史、指纹目录、管理员鉴权；在空测试分组验证自动策略保存、条件不匹配回退和切回手动模式，恢复该组原策略，全程不向外部上游发送请求。
- 浏览器核验分组卡片、筛选、分页、巡检设置、跨组选择去重、批量入口、历史证据、调度诊断与原始列表。

广泛运行历史测试时，仍有非本次功能的 Windows/基线问题：备份测试依赖 `sh`；Ollama 旧回调测试在未改动基线上也失败；内存上限与 CommandCode 全套上下文测试在整包运行失败、单独运行通过。没有因此删改测试。相关日志保存在本机 `quality-complete-backend-tests.log`、`quality-baseline-failures.log`。针对本次功能、调度、Ops 和协议路径的检查单独通过，不宣称全仓库所有测试全绿。

本地模拟检测不产生外部模型费用。用户在本地界面自行发起的真实手动测试及配置已保留；验收没有将所有账号自动巡检或自动权重强制开启。
