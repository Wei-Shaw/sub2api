# 计费与定价口径

本文统一说明后台配置、模型广场和使用记录中的价格术语。除非特别说明，金额单位为 USD。

## 一次请求的价格链路

```text
模型基础价
  → 上下文/服务等级/分时等适用价格因素
  → 用户有效倍率
  → 用户扣费
```

通常情况下，用户有效倍率的优先级是：

```text
用户在该分组的专属倍率 > 分组默认倍率 > 系统默认倍率
```

因此，分组倍率是“用户价格倍率”，不是上游账号成本倍率。

OpenAI API Key 账号可以额外启用账号级用户定价。实际选中该类账号后，倍率优先级变为：

```text
用户在该分组的专属倍率 > 账号级价格倍率 > 分组默认倍率 > 系统默认倍率
```

这里的 `>` 表示优先采用，不表示比较数值后取较大者。账号级价格倍率未启用时，完全沿用原有倍率链路。

## 价格来源优先级

模型基础价通常按以下顺序解析：

1. OpenAI API Key 账号逐模型完整价格（仅精确命中已配置的模型代号时）；
2. 分组逐模型定价；
3. 分组关联渠道的模型定价；
4. 动态模型价格表（model-price-repo / LiteLLM 数据）；
5. 本地价格文件；
6. 后端代码中的模型兜底价格。

账号、分组或渠道的显式模型价格会覆盖更低优先级的价格来源。账号逐模型完整价格只覆盖管理员逐项添加并精确命中的模型，不要求覆盖该账号允许调用的全部模型；未命中的模型继续走原有价格链路。

账号逐模型完整价格与账号级价格倍率可以同时启用：先使用命中的账号完整价格作为基础价，再应用有效倍率。界面会提示两项配置同时生效的影响。

## 长上下文价格

长上下文不是在普通分组倍率之外固定再乘一次。系统按以下规则处理：

- 配置了上下文区间时，按本次上下文数量选择对应价格档；区间价格已经包含该档差异，不再额外套用官方长上下文倍率。
- 没有显式区间但启用了长上下文价格时，使用模型官方/预设的长上下文规则。
- 分组关闭长上下文价格时，通常按最低/基础价格档；模型广场会提示官方阶梯仅供参考。
- Gemini 兼容旧路径可能使用“超过阈值的部分”边际计费，这是兼容路径，不应与统一区间价格混称。

## 账号成本与用户扣费

使用记录中的术语含义如下：

| 术语 | 含义 | 影响谁 |
| --- | --- | --- |
| 基础模型费用 | 模型单价乘以实际 Token/请求/图片等用量 | 计算基础成本 |
| 用户扣费 | 基础模型费用乘以用户有效倍率及适用价格因素 | 用户余额、订阅额度、API Key 配额 |
| 账号成本 | 基础模型费用乘以被选中账号的账号成本倍率 | 管理员成本和利润统计 |

账号成本倍率不会因为账号位于某个分组，就自动改变用户扣费。`账号成本倍率` 与 `账号级价格倍率` 是两个独立概念：前者用于管理员成本和利润统计，后者仅用于 OpenAI API Key 账号的用户扣费。

## 池模式

一个分组可以关联多个账号，系统会从账号池中选择账号并记录实际选中的账号。账号的 `pool_mode` 主要控制上游账号池场景下的失败重试、重试间隔和可重试状态码。

池模式本身不是新的收费模式。对于未启用账号级用户定价的账号：

- 用户价格仍由模型价格和分组/用户有效倍率决定；
- 账号 A 或账号 B 被选中，不应改变同一分组下的用户单价；
- 失败切换后，以最终成功请求的用量结算一次；
- 账号成本统计会记录实际承担请求的账号及其成本倍率。

对于 OpenAI API Key 账号池，管理员可以按账号配置逐模型完整价格和/或账号级价格倍率。此时最终选中的账号会参与本次用户价格计算，因此池内不同账号可以产生不同用户价格；同一账号无论加入多少个分组，其账号级配置始终一致。分组仍负责容纳账号和均衡调度。

## OpenAI API Key 账号级用户定价边界

- 仅适用于平台为 OpenAI、类型为 API Key 的账号；OpenAI OAuth、Setup Token 以及其他平台账号均不展示、不得写入，也不参与该链路。
- 旧账号的两个新字段为空，不触发新逻辑，无需迁移配置。
- 启用账号级用户价格倍率时必须显式填写大于 0 的倍率；不启用时没有默认账号级用户价格倍率。它与账号成本倍率相互独立。
- 逐模型完整价格按模型代号精确匹配，不做通配或模型家族猜测。
- 账号加入分组时不要求覆盖分组允许显示的全部模型；结算只检查本次实际请求并命中的模型。
- 若既没有命中账号完整价格，也没有启用账号级倍率，则该账号继续使用原有分组和基础价格规则。

## 配置时的推荐检查顺序

1. 先确认模型基础价来自分组、渠道还是默认价格表；
2. 再确认是否配置了上下文区间以及分组长上下文开关；
3. 确认用户是否有专属倍率；
4. 确认是否启用了 Fast/Priority、Flex、分时或高峰倍率；
5. 图片、视频等非 Token 模式单独检查其按张、按秒或独立倍率配置；
6. 若最终选中的是 OpenAI API Key 账号，再检查该账号是否命中逐模型完整价格、是否启用账号级价格倍率；
7. 账号池本身只负责容纳账号、路由和重试，价格变化来自最终选中账号的显式配置，而不是“池模式”这个名称。
