# 图片表达式计费：问题、配置与验证

## 解决什么问题

图片成本可能同时取决于模型、分辨率、质量和实际生成张数。现有 `ImagePriceConfig` 的 1K / 2K / 4K 三档和 `CalculateImageCost` 无法表达同一分辨率下的不同质量，也没有独立的 1.5K 档。把一个模型所有请求都收同一个价格，可能少收或多收；单纯提高分组倍率只能整体缩放，不能修复不同规格之间的价差。

本功能增加可选的、按客户端模型 ID 精确匹配的表达式。管理员在分组图片计费区配置公式；请求进入网关时冻结公式与计费参数，使用最终成功返回的图片张数结算。没有配置或没有匹配到的模型继续使用原有计价逻辑。

这是一项销售计价能力，不是上游账单查询或成本自动同步。管理员仍需维护价卡，并核对实际采购成本、充值折扣与倍率。当前 Sub2API 内置 Grok 价格也不是统一 $0.04，因此不能据此断言所有现有 Sub2API 实例都在亏损。

## Grok 官方价卡与固定价的差额

核查日期：2026-11-06。以下限于 `grok-imagine-image-2.0` 基础文生图，每次成功返回一张图片，不含输入图片、编辑、批处理优惠或其他供应商加价。

| resolution | quality | 官方输出价 / 张 | 假设统一收 $0.04，每 100 张少收 | 对应表达式档位 |
| --- | --- | ---: | ---: | --- |
| 1k | low | $0.04 | $0 | 1k-low |
| 1k | medium | $0.06 | $2 | 1k-medium |
| 1.5k | low | $0.05 | $1 | 1.5k-low |
| 1.5k | medium | $0.07 | $3 | 1.5k-medium |
| 2k | low | $0.06 | $2 | 2k-low |
| 2k | medium | $0.08 | $4 | 2k-medium |

来源：[xAI 模型定价](https://docs.x.ai/developers/models/grok-imagine-image-2.0)、[图片生成参数](https://docs.x.ai/developers/model-capabilities/images/generation)。生成文档中省略 resolution 默认为 1k，省略 quality / auto 在当前基础文生图下选择 low。模型定价页列出 1.5K，生成参数页目前只列出 1k / 2k；本功能保留 1.5k，不据此保证所有账号、区域和兼容渠道均接受该参数。

上述差额仅是同一美元口径、实收倍率 1× 时的示例，不是某个站点的真实亏损记录。设充值实际到账比例为 r、有效图片倍率为 m，则每张现金毛差额为 `表达式基价 × m × r − 上游实际成本`，尚未扣除支付手续费等。即使表达式与官网完全一致，m 或 r 小于 1 也可能造成亏损。图片比例在这张官方价卡中没有单独价格档；不应凭比例推算出额外 $0.13 的基础文生图价格。

## New API 的参考实现与边界

New API 已有表达式 / 阶梯计费语法。其问题不是完全不能动态定价，而是部分图片请求的 provider 自定义字段被存入 `ImageRequest.Extra` 后，没有进入冻结的计费参数，导致 `param("resolution")` 取不到值、落错档。

公开修复：[QuantumNous/new-api#8227](https://github.com/QuantumNous/new-api/pull/8227)。它把 Extra 中的标量字段合并进冻结计费上下文，并保留已知字段优先级。核查时该 PR 为 OPEN；不能把它描述成所有正式版本已经包含的修复。

采用该修复和下面的公式后，团队反馈的 New API 实测记录已经按 1k-medium=$0.06、1.5k-low=$0.05、1.5k-medium=$0.07、2k-low=$0.06、2k-medium=$0.08 分档。这是调用方提供的成功计费记录，不是本 PR 发起的付费测试，也不等于 xAI 账单逐笔对账。1k-low、默认值和多张的预期另由价卡与本 PR 的自动化测试覆盖。

此处只采用公开 PR、合成请求和文本价卡示例；不包含任何用户截图、站点配置、私有文档、账户或账单数据。

## 配置与公式

在分组的“图片生成计费”中，新增模型 `grok-imagine-image-2.0`，选择 Grok 预设，检查图片有效倍率。表达式返回 **本次请求的总美元价格，尚未乘图片倍率**。单价公式必须显式乘 `image_count`；系统不会再乘一次图片张数。

```text
((param("resolution") == nil || param("resolution") == "1k")
  ? (param("quality") == "medium"
      ? tier("1k-medium", fixed(0.06))
      : tier("1k-low", fixed(0.04)))
  : param("resolution") == "1.5k"
    ? (param("quality") == "medium"
        ? tier("1.5k-medium", fixed(0.07))
        : tier("1.5k-low", fixed(0.05)))
    : param("resolution") == "2k"
      ? (param("quality") == "medium"
          ? tier("2k-medium", fixed(0.08))
          : tier("2k-low", fixed(0.06)))
      : tier("unrecognized-resolution", fixed(0.08))) * image_count
```

该公式可用于上述 New API 修复后的表达式计费，亦为本功能的兼容语法子集示例。Sub2API 中 `fixed(x)` 直接返回美元数值，不使用 New API 内部结算单位。

最后一档 $0.08 是管理员选择的兜底价格，不是未知规格的官方定价，也不会自动拒绝未知规格。quality 非 medium 时选择 low，包括当前默认的 auto；若供应商新增质量档或更改 auto 行为，必须更新公式或限制渠道接受的规格。不要宣称此预设能自动跟随未来价格。

合成请求：

```json
{
  "model": "grok-imagine-image-2.0",
  "prompt": "A red ceramic cup on a plain desk",
  "resolution": "2k",
  "quality": "medium",
  "aspect_ratio": "16:9",
  "n": 3
}
```

预估基价 $0.24（非单调公式会预留所有不超过请求数量的结果中的最大费用）；如果成功返回 2 张，基价 $0.16；如果图片有效倍率为 1.25，实收 $0.20。`param("n")` 仍为请求时的 3，`image_count` 为实际成功返回的 2。不能使用请求 n 代替实际张数结算。

## 数据与表达式契约

管理 API 的创建和更新字段：

```json
{"image_price_expressions":{"grok-imagine-image-2.0":"fixed(0.04) * image_count"}}
```

- 配置在分组级，以**客户端请求模型名**精确匹配，区分大小写，不支持通配符。不依赖账号或渠道映射后的计价模型名；别名应分别配置。
- PATCH/更新省略字段或传 null 保留配置；传 `{}` 清空；传非空对象整体替换，未提交的旧模型将移除。复制分组和认证缓存使用独立 map。
- 命中表达式优先于旧图片固定价、1K / 2K / 4K 价和 token 模式。未命中时保持原逻辑。模型广场对命中模型展示动态价格及公式，不展示旧固定价作为实收价。
- `image_count`：预估时为请求张数，结算时为实际成功输出张数。
- `param("n")`：冻结的请求张数；`param("model")`：客户端模型 ID；`param("resolution")`、`param("quality")`、`param("aspect_ratio")`、`param("size")`：计费使用的标量事实，缺失字符串为 nil。Grok geometry 适配必须与最终发送参数保持一致。
- `fixed(USD)` 返回 USD；`tier("名称", 金额)` 返回金额并记录档名。支持条件表达式、比较、逻辑运算和基本四则运算。此版本不支持任意请求头、prompt、嵌套对象、文件、网络访问、时间函数、循环或任意代码。
- 最多 64 个模型配置，模型名最多 200 字节，每条公式最多 4096 字节和 256 个 AST 节点，档名最多 50 字节以适配 usage 日志列；数量上限 128，公式金额及乘倍率后的金额必须有限、非负且不大于 $1,000,000。供应商更低的数量限制仍然适用。
- 保存时做语法、允许字段和常见参数组合检查；转发前针对当前请求预检，不能把计算失败降级为旧价或免费。配置错误必须在上游产生费用前暴露。
- 请求快照与稍后的配置更新隔离；实际倍率沿用现有独立图片倍率 / 分组有效倍率规则，只应用一次。成功返回后的数量调整使用同一公式和参数。

## 首版支持范围与限制

本次支持 OpenAI 兼容 API Key 通道和 Grok 图片入口上的同步 JSON `POST /v1/images/generations` 基础文生图。表达式不是对所有图片、聊天、任务和 provider 协议的通用补丁。

启用表达式的模型用于编辑 / 输入图、multipart、流式、deferred、异步任务、持久批量任务、原生 Gemini、Chat / Responses / Messages 或 OpenAI OAuth 协议转换时，必须在发往上游前明确拒绝，不能退回旧价继续收费。未配置表达式的模型不受这些新限制。未来扩展需先补齐各入口的参数归一化、实际图片计数和事务结算合同。

当前使用既有 usage 日志的金额、图片张数与 BillingTier 字段记录结果；没有新增完整公式版本及参数快照的持久化审计表。因此此版本不能从历史日志完整重放每笔表达式。请求期间的冻结快照用于一致结算，长期财务对账仍应保留供应商账单及受控的价卡版本记录。

本功能不改变充值、优惠、订阅额度、退款策略，也不承诺请求失败重试过程中供应商的计费规则与本站一致。上游若对失败尝试收费、只返回部分图片却收全部费用，或返回事实与请求承诺不一致，仍需单独对账。

## 验收与回退

必须覆盖：六个 Grok 档位；缺省 / auto；1.5k 不被归并为 2K；请求 3 张返回 2 张；零成功图片；倍率只应用一次；配置更新不影响在途请求；分组复制及缓存隔离；非法表达式在调用上游前拒绝；关闭在途预留或订阅模式不能绕过预检；未支持入口不能绕过表达式；无表达式配置的旧请求保持兼容；模型广场不展示误导性的固定价。

迁移 250 仅增加 nullable JSONB 字段，不修改已有价卡和余额。部署后默认不开启任何模型表达式；先升级全部网关实例，再由管理员逐个配置启用，避免旧实例不认识新配置。回退时先清空表达式配置并让在途请求完成，再恢复旧二进制；旧版本忽略该新增列。不要在仍有表达式请求在途时切换价格或降级并假设结算语义不变。上线前建议用测试分组对照官方账单验证六档、多张和实际倍率。
