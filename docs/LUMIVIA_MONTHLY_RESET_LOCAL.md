# 月额度扣时重置

用户可在“我的订阅”的每月额度下点击“重置月额度”，查看将扣除的时长和新的到期时间，确认后提前进入下一个月额度周期。

## 规则

- 仅限用户自己的有效订阅；分组必须启用、使用订阅计费并配置月限额。
- 月窗口已开始、有月用量且尚未自然到期，订阅到期时间必须晚于本月重置时间。最后一个月没有下一周期时应先续费。
- 扣除时长 = 确认时刻距离本月重置时间的剩余时长。新到期时间 = 原到期时间 − 扣除时长；月用量清零，月窗口从确认时刻重新开始。
- 周窗口同步推进相同时长，越过周重置边界时清零周用量，没有越界则保留；日窗口和日用量保持不变。
- 例如本月剩 2 天、订阅共剩 32 天，确认后订阅约剩 30 天，并开始新的月额度周期。不会免费补发月额度。

## 接口与一致性

`GET /api/v1/subscriptions/:id/advance-month` 预览，`POST` 同路径确认。确认体包含预览返回的 `monthly_window_start`、`weekly_window_start`（字段必传，允许 `null`）和 `expires_at`。

最终扣时按确认时刻重算。事务内锁定订阅并核对预览的周/月窗口和到期时间，一次更新相关字段；重复请求或过期预览返回 409，越权返回 404。事务成功提交后失效订阅及计费缓存。

不需要新增数据库字段或迁移。页面仅保留“重置将扣除本月剩余时长”提示，具体扣时和到期时间在确认弹窗展示。

## 套餐有效期

套餐设置使用 `validity_days=1`、`validity_unit=months`，后台与售卖卡片显示“1 月”。现有 `psComputeValidityDays` 将一个月换算为 30 天，本功能没有改成自然月算法。

套餐有效期是数据库配置，代码更新不会自动批量修改套餐或已购买订阅。调整现有 Codex 套餐时，应读取目标环境当前数据，仅更新指定套餐的有效期数值和单位。

## 验证与后续更新

覆盖月额度扣时、最后周期限制、旧窗口兼容、周窗口同步、日字段保留、越权与重复确认，以及提交后缓存失效。前端测试覆盖预览、取消、提交、冲突后刷新和禁用条件。

本地 HTTP 与 PostgreSQL 并发验证中，同一预览的 6 次确认仅 1 次成功，另外 5 次返回 409；本地页面和 390px 手机宽度已验收。测试数据与数据库备份不随仓库发布。

Lumivia Release 在发布镜像前检查周/月重置的核心测试存在并执行回归测试，防止同步官方更新时遗漏定制功能。推送 main 会构建并上传 GHCR 镜像，服务器部署由独立更新流程执行。
