# 部署后快速上手

本文面向已经完成部署、能够打开 Sub2API 登录页的用户，走通「添加上游账号 → 绑定分组 → 创建 API 密钥 → 发起请求」这一条最小使用流程。部署和初始化步骤见 [中文 README](../README_CN.md)。

以下以**标准模式、OpenAI API Key 账号、支持 Chat Completions 的文本模型**为例。OAuth 账号需要在添加账号时完成对应平台的授权；不要把 OAuth 授权凭据当作客户端 API 密钥。

## 1. 登录管理后台

使用初始化时创建的管理员账号登录自己的站点，例如 `http://localhost:8080`。如果首次访问仍显示设置向导，先完成数据库、Redis 和管理员账号配置。

下面的 `/admin/...` 和 `/keys` 都是**自己站点内的页面路径**。

## 2. 创建分组

进入 **分组管理**（`/admin/groups`），创建一个分组：

- 平台选择 **OpenAI**，与接下来添加的上游账号一致。
- 订阅类型选择 **标准（余额）**，计费倍率先保留默认值。
- 首次验证可使用公开分组；使用专属分组时，需要为调用者授予该分组权限。

分组把上游账号与客户端 API 密钥连接起来：密钥绑定哪个分组，请求就从该分组的可用账号中调度。

## 3. 添加并测试上游账号

进入 **账号管理**（`/admin/accounts`），添加账号：

1. 填写便于识别的账号名称，平台选择 **OpenAI**，账号类型选择 **API Key**。
2. 填入**上游提供的 API Key**。使用官方 OpenAI API 时，Base URL 留空即可；使用兼容服务时，填写该服务提供的 API 地址。
3. 在分组选择中勾选上一步创建的分组，保存账号。
4. 在账号列表的操作菜单中选择 **测试连接**，选择上游实际支持的模型，确认能够收到回复。

需要代理时，先在 **IP管理**（`/admin/proxies`）添加代理，再在账号中选择它。这里的代理负责 Sub2API 服务器连接上游。

测试失败时先检查上游密钥、地址、模型权限和服务器网络。账号测试成功后，再验证下面的客户端调用；两者经过的用户权限与余额检查不同。

## 4. 准备调用者与 API 密钥

在标准模式下，调用者需要有可用余额。管理员可在 **用户管理**（`/admin/users`）为自己的账号或测试用户调整余额，并确认用户可以访问刚创建的分组。

然后以该用户登录，进入 **API 密钥**（`/keys`）；管理员可从 **我的账户 → API 密钥** 进入：

1. 点击创建，填写密钥名称。
2. 选择刚才的分组，保存并复制生成的密钥。

这把 **Sub2API 生成的密钥**用于客户端请求，与第 3 步填入后台的上游密钥不同。不要把上游密钥交给使用 Sub2API 的客户端。

## 5. 发起一次请求

客户端的 Base URL 填自己的 Sub2API 地址加 `/v1`，例如 `http://localhost:8080/v1`；API Key 填第 4 步生成的密钥。

以下命令使用 Bash。将站点地址、密钥和模型 ID 替换为自己的值：

```bash
curl 'http://localhost:8080/v1/models' \
  -H 'Authorization: Bearer YOUR_SUB2API_KEY'
```

模型列表用于查看当前分组提供的模型 ID；列出模型不代表上游账号已经通过实际调用测试。选择第 3 步已测试、支持 Chat Completions 的模型发起请求：

```bash
curl 'http://localhost:8080/v1/chat/completions' \
  -H 'Authorization: Bearer YOUR_SUB2API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "YOUR_MODEL_ID",
    "messages": [{"role": "user", "content": "Reply with hello."}],
    "stream": false
  }'
```

收到回复后，在 **使用记录**（`/usage`）中查看这次请求的模型、Token 和费用；管理员也可以在 `/admin/usage` 查看记录。

## 常见卡点

| 现象 | 优先检查 |
| --- | --- |
| 创建密钥时找不到分组 | 分组是否启用，调用者是否拥有该分组权限 |
| 账号测试成功，客户端仍无法调用 | 客户端是否用了 Sub2API 密钥、绑定了正确分组，调用者余额及密钥限额是否充足 |
| 提示没有可用账号 | 分组是否关联账号，账号是否启用调度，是否过期、限流或不支持请求的模型 |
| 返回 401 | 密钥是否正确、有效，Authorization 是否使用 `Bearer` 格式 |
| 客户端返回 404 | Base URL、客户端使用的 API 协议及上游模型是否匹配，是否重复拼接了 `/v1` |

需要使用订阅套餐和在线支付时，再参阅 [支付配置说明](PAYMENT_CN.md)。本文的首次调用流程无需配置支付服务商。
