## 升级与回退

本轮没有新增 SQL migration、Ent/Wire 图、依赖或缓存格式版本。图片档位缺省、空列表、无有效档位
或三档全选均沿用不限尺寸。旧节点会忽略新的 extra 字段，因此必须等所有调度和账号写入节点升级后
再设置限制；回退前恢复全部档位，并等待账号快照刷新。保留既有数据库及历史账单，不执行 Down SQL。

显式尺寸按最长边分为 1K（≤1024）、2K（≤2048）和 4K；`2560x1440` 属于 4K。
未传、auto 或无法识别的尺寸优先不限档位，再依次尝试允许 4K、2K、1K 的账号。最多四轮，已有
会话或 previous_response 绑定在没有显式尺寸时继续遵守本项目原策略；后续溢出轮次不得删除或抢占
仍有效的绑定。只有实际获取槽位后才处理溢出绑定，利润准入仍由当前 owner 完成。

混合版本期间，空指令请求、回显、Kimi 冷却和 Grok 委派兼容性只在新节点生效，应完成全节点升级后
再依赖这些行为。导出增强只在新前端生效，原列表接口和响应格式保持兼容；导出仍在浏览器内形成文件，
没有增加服务端任务、无界后台队列或持久导出存储。

## 性能与验证

图片候选过滤不创建档位切片；正常文本请求不启动尺寸轮次。尺寸偏好沿用原调度器，最多四次有界尝试，
没有引入常驻 worker。无法满足显式档位时的持久候选查询仅用于错误分类，不进入正常转发热路径。
Antigravity 对输入集中编码一次；指令回显不扫描 token delta。固定夹具的 Docker 性能与验证结果见
[验证记录](../diagnostics/upstream-sync-20261104/VERIFICATION.md)，不外推生产吞吐或实际故障率。

账号创建的 OpenAI extra 构造按职责迁至同 feature 的 `accountCreateOpenAIExtra.ts`，保持同步调用和
原有表单生命周期。批量更新以 null 表示不修改，显式空数组清除限制；编辑保留已构造 payload 的删除语义，
不会用旧账号 extra 复活被关闭的其他选项。
