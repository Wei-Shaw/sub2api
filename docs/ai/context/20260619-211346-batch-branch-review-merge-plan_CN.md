# 分批分支、自审与合并计划

## 背景

当前 `main` 工作区存在多组未提交修改，用户要求按批次创建新分支，在新分支提交修改，然后逐批自审并合并回 `main`。

## 拆分原则

- 按行为边界拆分，避免一个提交同时改变后台注册逻辑、前端支付流程和迁移脚本。
- 不提交本机备份、数据库 dump、sqlite 快照、运行态 env 文件。
- 对被 `AGENTS.md` 引用的上下文文件使用 `git add -f` 显式纳入，避免提交后出现断引用。
- 每批合并前先看 diff，再运行与该批直接相关的测试。

## 批次

1. 用户名兜底批次：后台创建/注册用户时保证 `username` 有值，前端管理员用户列表展示空用户名时回退到邮箱。
2. 手动扫码支付批次：无支付服务商配置时，订阅购买打开手动付款弹窗，不创建订单，引导用户用兑换码开通。
3. 迁移与协作记忆批次：修正旧 Key 迁移默认分组，并提交压缩后的协作记忆和必要上下文。

## 排除项

- `.tmp-*`
- `deploy/.env.scheme-a.runtime`

这些文件属于本机备份、数据库快照或运行态配置，不进入 Git 历史。
