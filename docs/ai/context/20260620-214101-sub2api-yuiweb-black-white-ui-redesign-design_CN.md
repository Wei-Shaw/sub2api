# Sub2API 前端 yui.web 黑白灰视觉重设计设计稿

## 背景

用户希望使用当前 `yui.web` 项目的配色风格，整体修改当前 `sub2api` 的前端页面配色和 UI。已按 `using-superpowers` 与 `brainstorming` 流程确认修改边界：本次只修改前端页面，不改后端、数据库、API、路由、计费和运行态配置。

## 已确认边界

- 覆盖范围：用户页和管理后台一起改，做到全站一致。
- 风格方向：采用 `yui.web` 的作品集黑白灰风格，不采用 `/shop` 入口沉浸大图风格。
- 修改深度：保留现有信息架构，只统一视觉系统；不重排业务页面结构。
- 深色模式：保留并同步改成 `yui.web` 的黑灰暗色体系。
- 字体：标题和品牌展示使用 `Playfair Display`，正文和表格使用 `Inter`，失败时回退系统字体。
- 品牌：深度品牌化，但限定在前端呈现层；默认品牌名使用「天才程序员小站」。
- Logo：保留现有后台配置优先逻辑；未配置时才展示新默认品牌或低调黑白默认标识。
- 状态色：采用极致黑白灰；除错误红色等必须警示场景外，成功、警告、平台、模型、支付状态尽量使用灰阶、边框、图标和文字区分。
- 实现策略：采用方案 2「设计系统收拢」，先建立统一 token 和组件基线，再系统修改布局、基础组件和关键业务组件。

## 视觉系统

迁移 `yui.web` 的黑白灰作品集气质：

- 浅色主基调：`#ffffff`、`#fafafa`、`#222222`、`#666666`、`#e5e5e5`。
- 深色主基调：`#0f0f0f`、`#1a1a1a`、`#242424`、`#333333`、`#e5e5e5`。
- 点缀色：少量米色或金色只用于选中态、焦点态或极少数强调，不做大面积彩色背景。
- 圆角：整体收敛为小圆角，接近 `yui.web` 的 `0.25rem` 到 `0.75rem`。
- 阴影：使用低强度轻阴影；移除当前青绿色发光、玻璃拟态和 mesh 背景。
- 字体：`font-display` 对应 `Playfair Display`，`font-sans` 和正文对应 `Inter` 加系统字体回退。

## 组件设计

全局组件基线应先收拢：

- `tailwind.config.js`：重写 `primary`、`accent`、`dark` 色板，使现有 `text-primary-*`、`bg-primary-*` 自动落到黑白灰体系。
- `style.css`：重做 `.btn`、`.input`、`.card`、`.table`、`.badge`、`.modal`、`.dialog`、`.sidebar`、`.tabs`、`.progress` 等基础类。
- 按钮：主按钮黑底白字，深色模式反相或高对比灰阶；次按钮白底细边框；危险按钮保留红色。
- 输入框：白底或深灰底，细边框，焦点态使用黑/白/少量金色，不使用青绿色 ring。
- 卡片：白底或深灰底，细边框，轻阴影，不使用大圆角和玻璃透明。
- 表格：表头使用低对比浅灰/深灰，行 hover 使用轻微灰阶，不依赖彩色强调。
- 徽章：默认灰阶；状态差异通过边框、背景深浅、图标、文本说明表达。
- 弹窗和 Toast：保留可用结构，外观统一为黑白灰；错误 Toast 可保留红色边框。

## 页面设计

- `AppLayout`：背景改为纯净浅灰或黑灰，不再使用青绿色 mesh。
- `AppSidebar`：白/黑背景、细边框、灰阶选中态；品牌标题使用 display 字体。
- `AppHeader`：保留功能区；余额、语言、公告、用户菜单改为低对比灰阶控件。
- 首页：保留当前内容结构，去掉彩色渐变和发光背景，改成作品集式标题、细边框信息块、黑白 CTA。
- 认证页：参考 `yui.web` shop/auth 的白底细框和 display 标题，主按钮黑底。
- 用户页：仪表盘、Key、用量、订阅、支付、兑换等页面不改业务组织，只统一卡片、表格、标签、提示块和弹窗。
- 管理后台：Dashboard、Users、Accounts、Groups、Settings、Orders、Ops 等页面统一套用新组件基线，优先处理彩色统计卡、平台色、模型标签和图表配色。
- 支付页：外层面板和订单状态灰阶化；第三方支付按钮可保留最低限度识别，但不让它主导页面风格。

## 实现边界

- 只修改 `frontend/` 下页面、组件、样式、前端默认展示文案和必要资源引用。
- 不修改 `backend/`、迁移脚本、部署配置、数据库数据、API 行为。
- 不修改路由结构和业务流程。
- 不删除后台自定义 `siteName/siteLogo` 能力。
- 不覆写、重命名或删除 `docs/ai/context/` 历史文档。

## 风险与取舍

- 颜色类分散在 `.vue` 和 `.ts` 文件中，单靠 Tailwind 色板不能完全消除彩色残留，需要集中处理平台色、模型标签、统计卡、支付状态和图表颜色。
- 极致灰阶会降低状态辨识度，因此必须用文字、图标、边框、深浅和排版补足。
- Google Fonts 在部分网络环境可能不稳定，必须保留系统字体回退，页面可用性不能依赖外部字体。
- 管理后台页面很多，完成后需要抽查代表页面，避免局部仍保留青绿色 SaaS 风格或文本对比不足。

## 验证计划

- 运行前端类型检查或构建：优先 `pnpm build`，必要时补充 `pnpm typecheck`。
- 浏览器检查浅色和深色模式代表路径：`/`、`/login`、`/dashboard`、`/keys`、`/purchase`、`/admin/dashboard`、`/admin/users`、`/admin/accounts`、`/admin/settings`。
- 搜索残留彩色类：重点检查 `teal`、`cyan`、`emerald`、`blue`、`purple`、`glow`、`mesh-gradient`。
- 验收标准：用户端和管理端都统一为 `yui.web` 黑白灰作品集控制台风格；默认品牌显示「天才程序员小站」；错误状态仍清晰可见；业务流程不变。

## 自审

- 无占位符、无待定项。
- 设计范围与用户确认的 B/A/A/A/A/C/「天才程序员小站」/A/B 边界一致。
- 设计未要求修改后端、数据库、API、路由或计费逻辑。
- 风险和验证覆盖了灰阶状态辨识、字体回退、彩色残留和代表页面检查。
