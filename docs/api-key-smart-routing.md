# API 密钥智能路由

在用户的「API 密钥」创建或编辑弹窗中，选择「智能路由」，添加 1–10 个 OpenAI 兼容分组。上移、下移按钮调整优先级；第一个分组优先尝试。保存后，密钥列表展示智能路由标识和分组顺序。切回「固定分组」并保存即可关闭智能路由。

## 首批范围

- 支持 HTTP Chat Completions 和 Responses 文本请求及其既有路径别名。
- 分组平台为 OpenAI、Grok、Kimi、Zhipu、DeepSeek、MiniMax。
- 按配置顺序匹配模型目录与可调度账号。未知模型、空模型不会作为任意模型透传到首组。
- 模型目录来自明确的账号模型映射；无映射的 OpenAI 账号使用项目默认 OpenAI 模型目录。自定义模型应由管理员配置明确的模型映射。
- 选组时重新验证用户权限、分组状态和有效订阅。分组的模型白名单仍然生效。
- 正式调度结果随请求传入处理器，沿用现有并发、利润准入和组内重试逻辑。上游已处理请求后的重试仍在所选组内。
- 请求按实际选中分组的费率、用户专属倍率或订阅扣费；密钥额度和限额仍属于同一把密钥。
- 模型列表聚合可访问路由分组的目录。Responses 的 `previous_response_id` 继续验证用户与密钥所有权，并限定在原所属分组。
- WebSocket、图片生成及其他接口不在首批范围，需使用固定分组密钥。

## API 与数据

用户密钥创建、更新接口新增 `routing_group_ids`，数组顺序即路由顺序。例如：

```json
{
  "name": "文本智能路由",
  "group_id": 12,
  "routing_group_ids": [12, 21, 35]
}
```

非空数组开启智能路由，后端将 `group_id` 设为首个分组。更新时省略数组保留原配置，显式传 `[]` 关闭智能路由，并使用同时提交的固定 `group_id`。不允许重复 ID、非正 ID、超过 10 个分组或无权使用的分组。

迁移 `238_api_key_smart_routing.sql` 为 `api_keys` 增加可空 JSONB 列 `routing_group_ids`；旧密钥默认保持固定分组行为。Ent 代码通过既有生成流程更新。认证快照包含有序 ID，实际分组和权限在请求时加载。

## 验证与发布

发布前验证密钥配置保存与回显、路由顺序、权限变更、模型不匹配与容量不足、所选分组计费、并发资源释放，以及已有固定分组行为。上线只更新目标 Sub2API 应用，核对迁移完成、应用健康、Caddy 与公网入口；不重建共享数据库、缓存或数据卷。

默认先提交并推送 GitHub，再由服务器拉取指定提交、构建并切换目标应用镜像；本地构建和传输镜像仅作回退方案。

多分组智能密钥不提供单一分组的 `/v1/sub2api/billing` 倍率自省，以免托管客户端误用首组价格；依赖该接口的客户端应使用固定分组密钥。
