# 学生资格认证设计

日期：2026-09-27
状态：已与需求方确认，待实施

## 背景与目标

为 Sub2API 自家用户提供「学生资格认证」。认证通过后授予两项权益：

1. **专属分组**：管理员预先按平台创建的专属标准分组（多平台），认证用户的 `AllowedGroups` 并入这些分组，用户可自行把 API Key 绑定到学生组。
2. **专属邀请返利**：学生作为邀请人时，其返利比例从全局值（如 5%）提升为学生专属值（如 10%）。被邀请人是否学生不影响返利。

学生认证是资格（entitlement），不是登录身份；不改 `users.role`、不改注册/登录流程。

## 已确认决策

| 决策点 | 结论 |
| --- | --- |
| 核验方式 | 学校邮箱验证码，全自动，无人工审核 |
| 邮箱占用 | 一个学校邮箱全局只能被一个账号认证；同一用户可重验续期或换绑新邮箱（旧邮箱即时释放） |
| 有效期 | 固定期限（默认 12 个月，管理员可配置天数）；到期自动失效 |
| 续期 | 到期前后同一用户可用原邮箱重新验证，延长有效期；邮箱不能换绑到其他账号 |
| 学生组来源 | 管理员先按现有流程创建专属标准分组，再在学生认证设置中勾选哪些组属于学生组 |
| 撤销 | 管理员可撤销；撤销/到期走同一移除权益的路径。记录保留，邮箱占用不释放，仅管理员删除记录才释放邮箱 |
| 返利语义 | 学生作为邀请人享受专属返利比例，覆盖全局值 |

## 数据模型

新建 `student_verifications` 表（ent schema + 迁移）：

- `id` int64 PK
- `user_id` int64，唯一索引（一个用户同时只有一条认证记录）
- `email` string，规范化后的学校邮箱（`NormalizeEmailForAliasDedup` 归一化，防 `+alias` 变体绕过），唯一索引（一个邮箱只能被一个账号认证）
- `email_raw` string，用户输入的原始邮箱，仅用于展示
- `status` string：`active` / `expired` / `revoked`
- `verified_at` timestamptz
- `expires_at` timestamptz
- `revoked_at` / `revoked_by` / `revoke_reason` 可空
- `rebate_rate_applied` float64 可空：认证时写入的学生返利比例
- `previous_rebate_rate` float64 可空：认证前该用户原有的个人专属返利比例，用于撤销时恢复
- `created_at` / `updated_at`

唯一性约束是该需求的正确性根基：发码阶段做快速查重（友好报错），提交验证码时在事务内插入，撞唯一索引即返回「该邮箱已被其他账号认证」。

## 设置项（管理员，SystemSetting）

- `student_verification_enabled` bool
- `student_verification_email_suffixes` 域名白名单：复用注册域名策略的通配符匹配（`*.edu.cn`、`edu.cn`、具体域）。与注册白名单相互独立
- `student_verification_validity_days` int，默认 365
- `student_verification_group_ids` []int64：学生组集合，校验必须是 active 的专属标准分组
- `student_verification_rebate_rate_percent` float64：学生专属返利比例，写入 `user_affiliates.aff_rebate_rate_percent`

## 用户端流程

个人设置页新增「学生认证」卡片，按状态渲染：

- 未认证/已过期/已撤销：邮箱输入框 -> 「发送验证码」-> 验证码输入 -> 提交
- 已认证：显示认证邮箱（脱敏）、到期时间、已获得的分组与返利说明

后端接口（登录态）：

- `GET /api/v1/user/student-verification`：当前状态、脱敏邮箱、到期时间
- `POST /api/v1/user/student-verification/send-code`：校验总开关、域名白名单、邮箱占用；复用 `emailService.SendVerifyCode`，继承其冷却/频率限制
- `POST /api/v1/user/student-verification/verify`：校验验证码；事务内完成：插入/更新认证记录 -> 合并学生组到 `AllowedGroups` -> 写返利比例（先存 `previous_rebate_rate` 再覆盖）-> 失效鉴权缓存

续期：同一用户携带已认证邮箱重验 -> 更新同一行 `verified_at`/`expires_at`，分组与返利幂等重写。换邮箱：先用新邮箱走完整验证流程，成功后事务内更新同一行（旧邮箱约束随更新释放）。

## 失效路径

定时任务（复用现有调度基础设施，间隔数分钟）：

1. 扫描 `status=active AND expires_at < now` 的记录
2. 每条事务内：状态置 `expired` -> 从该用户 `AllowedGroups` 移除当前配置的学生组 -> 返利比例恢复（见下）-> 清鉴权缓存

管理员撤销走同一移除函数，状态为 `revoked` 并记录操作者。

返利恢复规则：仅当 `user_affiliates.aff_rebate_rate_percent` 当前值仍等于 `rebate_rate_applied` 时才恢复为 `previous_rebate_rate`；若管理员期间手动改过该用户比例，不动管理员值。

权益移除只删 `AllowedGroups` 中的学生组项，不碰其他组、不解绑 Key——已绑学生组的 Key 由网关 `GROUP_NOT_ALLOWED` 校验自动拦截，用户重新认证后可继续使用。

## 管理端

- 系统设置新增「学生认证」分区：总开关、域名白名单、有效期天数、学生组多选（拉取专属标准组列表）、学生返利比例
- 认证记录列表：用户、邮箱（脱敏）、状态、认证时间、到期时间、操作（撤销）
- 撤销为显式二次确认操作，记录操作者；提供删除记录入口用于释放邮箱（售后兜底）

## 安全与边界

- 验证码复用现有发码/验码服务，继承过期时间、尝试次数与冷却限制；不在日志中打印验证码与完整邮箱
- 认证接口需登录态；发码接口校验域名白名单后才发信，避免被当邮件轰炸跳板
- 邮箱唯一性由数据库约束兜底，应用层查重只做友好报错
- 返利总开关关闭时专属比例照常写入但不产生结算（与现行逻辑一致）
- 不收集学生证等敏感材料；学校邮箱仅证明邮箱归属，作为初筛信号已被需求方接受

## 非目标

- 不做第三方学生认证（SheerID 等）、不上传证件、无人工审核队列
- 不新增登录方式，不改注册流程
- 不自动创建分组、不自动创建 API Key、不自动改绑存量 Key
- 学生身份不给予注册/登录的任何特殊通道

## 测试要点

后端：

- 邮箱唯一性：并发认证同一邮箱仅一个成功；`+alias` 归一化
- 续期：同用户同邮箱重验更新到期时间；换邮箱释放旧占用
- 权益授予：学生组合并入 `AllowedGroups`（去重、不影响已有组）；返利覆盖与 `previous_rebate_rate` 记录
- 到期清扫：状态流转、学生组移除、返利恢复（含管理员已改值不覆盖）、缓存失效
- 撤销：同到期路径 + 操作者记录
- 域名白名单：通配符匹配、关闭时接口行为
- 验证码：未发码/错误码/过期码拒绝

前端：

- 认证卡片各状态渲染（未认证/已认证/临期/过期/撤销）
- 发码冷却倒计时、错误提示
- 管理端设置表单校验与认证记录列表/撤销交互
