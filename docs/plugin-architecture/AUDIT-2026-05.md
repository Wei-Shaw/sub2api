## 2. W11 — Reuse 单点化

### T39 Decimal proto-wire codec 单源化
**问题:** host 端 `pricing_extension_client.go` 写了 `parseDecimalString` /
`formatFloatAsDecimalString`；plugin 端 `internal/decimalx/decimalx.go` 写了
`ToProtoString` / `FromProtoString` / `DecimalToProtoString`。两份独立实现违反
"复用" 原则。

**改动:** 上提到 `plugin-sdk/decimalx/`（新包）：
- `ToProtoString` / `FromProtoString` / `FromProtoStringOrZero` /
  `DecimalToProtoString` — NullDecimal ↔ 字符串 wire codec
- `FormatFloatString` / `ParseFloatString` — float64 ↔ 字符串 host 边界 codec

host 与 plugin 都 import 该单源；plugin 的 `internal/decimalx` 只保留
NullDecimal 值帮手（`FromFloat64Ptr` / `IsPositive` / `MustPrice` 等）。

### T40 Pubsub→Stream forward 抽象
`grpc_server.go` 的 `Subscribe` 与 `eventBusSubscribe` 共用相同的 for-select
转发循环，仅消息 wrapper 不同。抽出泛型 helper:

```go
func forwardPubsubToStream[T any](
    ctx context.Context,
    src <-chan *redis.Message,
    stream grpc.ServerStream,
    encodeMsg func(*redis.Message) *T,
) error
```

### T41 Outgoing metadata interceptor 工厂
SDK `runner_init.go` 的 `callerIdentity{Unary,Stream}Interceptor` 是 30 行
模板复制。提炼到 `plugin-sdk/grpcmeta.go`:

```go
func AppendOutgoingMetadataUnary(key, value string) grpc.UnaryClientInterceptor
func AppendOutgoingMetadataStream(key, value string) grpc.StreamClientInterceptor
```

`dialCore` 直接调用工厂，不再手写闭包。
