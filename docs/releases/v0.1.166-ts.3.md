# TokenSupply v0.1.166-ts.3

## Highlights

- Consolidates administrator email routing into one Email settings surface with channel-level switches, recipient groups, and the related subscription and balance behavior settings saved atomically.
- Reworks Ops monitoring around service-quality failures: user-caused policy and credential errors no longer degrade availability, health scores expose concrete deduction reasons, and monitoring settings now save as one validated unit with readable schedules and next-run times.
- Hardens managed Docker updates with an authenticated control-plane self-upgrade handoff, active-container identity checks, bounded recovery, and rollback to the previous deployer binary on helper failure.
- Adds upstream Passkey sign-in and account management, a configurable model plaza, safer scoped account/API-key updates, and model compatibility fixes.

## Fork Changes

- Keeps identity verification and password-reset email mandatory, while subscription, balance, account-quota, risk-control, refund, Ops alert, and scheduled-report routing follow their channel policies. Administrator recipient groups support bulk population, validation, and legacy-setting compatibility.
- Saves notification policy and fine-grained subscription-expiry/balance settings through one backend transaction boundary. Queue-level deduplication suppresses duplicate jobs, while SMTP delivery remains at-least-once: a duplicate email is possible if SMTP accepts a message but recording that acknowledgement fails. Sensitive queued payloads remain encrypted, and alert/report recipients continue to exclude disabled or unverified legacy entries.
- Classifies request outcomes into service availability, upstream/provider degradation, authentication/credential failures, user policy errors, and operational noise. Excluded-only traffic no longer activates business scoring, so infrastructure failures cannot be diluted by an empty business score. Ops cards and score tooltips show backend-owned deduction causes instead of generic advice.
- Replaces fragmented Ops saves with one atomic monitoring contract. Alert behavior, report schedules, thresholds, runtime settings, server timezone, and next executions are visible without moving channel ownership out of Email settings.
- Adds two v2 availability defaults without rewriting operator-modified alert rows. Exact untouched legacy defaults are disabled only in the repository read compatibility layer.
- Adds deployer control-plane upgrade state, immutable image/container verification, timeout/error visibility, and recovery from stale historical slot identity. The installer performs a transactional one-time bootstrap before an older deployer can use self-upgrade.

## Configuration And Migrations

- Adds optional `webauthn.enabled`, `webauthn.rp_display_name`, `webauthn.rp_id`, and `webauthn.rp_origins` configuration. Passkeys remain disabled by default. Production origins must use HTTPS, the RP ID is a domain without scheme/port/path, and every configured origin must belong to that RP ID.
- Adds `api.moonshot.ai` and `api.moonshot.cn` to the default security URL allowlist.
- Migration `197_add_ops_alert_rule_v2_defaults.sql` inserts two availability rules with `ON CONFLICT DO NOTHING` and performs no destructive or in-place data rewrite.
- Migration `198_passkey_credentials.sql` adds Passkey user-handle and credential tables. Migration `199_passkey_indexes_notx.sql` builds their indexes concurrently.
- All migrations are additive and remain readable by the previous application image during blue-green coexistence.

## Deployment And Rollback

- Before the first update from a deployer that predates the control-plane upgrade contract, run the reviewed host installer bootstrap once. It must verify the active container ID/version/port, Nginx route, socket-directory identity, and previous service state before changing the deployer control plane.
- Keep `v0.1.166-ts.2`, its immutable image digest, the current active slot, and the database backup until the new slot and control-plane upgrade have been observed healthy for at least five minutes.
- Deploy only through the managed updater with `expected_current_version` and a unique request ID. Stop on `degraded`, `rollback_failed`, route mismatch, container-identity ambiguity, migration lock timeout, or control-plane helper failure.
- Migrations `197-199` pass the managed rollback-compatibility policy. Normal image rollback to `v0.1.166-ts.2` remains supported; the previous deployer binary is also restored automatically if the control-plane handoff fails.

## Known Limitations

- Passkeys are unavailable until an administrator supplies valid WebAuthn RP configuration and enables the feature; production browser support also requires HTTPS.
- Hosts running the older deployer cannot perform their first control-plane self-upgrade solely from the application UI. The one-time installer bootstrap remains a deliberate prerequisite; subsequent compatible deployer upgrades use the managed handoff.
- Legacy Ops alert compatibility is read-time only. Operator-modified rows are intentionally preserved, while exact shipped legacy defaults remain stored and can reappear if rolling back to an older application that does not understand the compatibility mapping.
