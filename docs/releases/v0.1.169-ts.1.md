# TokenSupply v0.1.169-ts.1

## Highlights

- Tracks upstream `v0.1.169` while preserving the fork's managed Docker release and deployment controls.
- Corrects OAuth/Codex Fast pricing when the outbound request uses `priority` but the provider response reports `default` or an unknown service tier.

## Fork Changes

- Treats an explicit OAuth/Codex outbound `priority` tier as authoritative for billing. This prevents Fast requests from being charged at Standard when the provider omits or normalizes the tier in its response.
- Keeps API Key billing response-authoritative when the provider returns a recognized actual tier, including Standard and Priority.
- Applies channel service-tier multipliers once using the request-level tier snapshot.
- Uses the same decision path for normal usage, cyber-policy usage, HTTP/protocol conversion, Images, Embeddings, Chat/Responses, Messages, Grok, and WebSocket/WebSocket v2 flows.
- OAuth response-tier observations remain diagnostic only and no longer create a false service-tier mismatch or service-quality degradation signal.

## Upstream Changes

- Baseline: fork `v0.1.168` -> upstream `v0.1.169` at `682c4fe0e61b851508fa976ac693e0f68a0639eb`.
- The upstream merge was kept as a real merge commit in PR #40 (`fd815544ae4bcc3358397f6234281b08fc5f704e`), preserving upstream ancestry.
- Relevant upstream changes include the current model-pricing/resource updates and the upstream application changes included in the `v0.1.169` baseline.

## Configuration And Migrations

- No database migration is added by this release.
- No new environment variable or administrator setting is required.
- Existing channel service-tier permissions and multipliers remain compatible with the previous release.
- The release is schema-compatible for blue-green deployment; the previous completed version remains a rollback candidate.

## Deployment And Rollback

- Publish and deploy only through the managed Release workflow and deployer. Do not create a tag locally.
- Before production deployment, verify the completion ledger, OCI digest, active version, active container, public health, and `degraded=false`.
- The application update remains blue-green. Keep the previous completed image and slot available until the new version has passed health, routing, background-job, and billing observations for at least five minutes.
- If billing or application health is incorrect, disable the affected channel tier or roll back to the previous completed release. Because this release has no migration, application rollback remains schema-compatible.

## Known Limitations

- Provider-specific service-tier reporting can still be absent or normalized in responses; OAuth outbound evidence is intentionally used for billing in that case, while the observation remains available for diagnostics.
- The existing managed-deployer limitations, including the need for a Bundle Installer when a host's control-plane extraction path itself is broken and the lack of automatic old-image retention, remain unchanged.
- No production Fast canary is included in CI. After deployment, verify a controlled OAuth/Codex Fast request and its recorded billing tier before treating the rollout as complete.
