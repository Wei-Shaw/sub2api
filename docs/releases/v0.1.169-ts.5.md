# TokenSupply v0.1.169-ts.5

## Highlights

- Fixes Image Playground reference-image uploads failing with `group_id is required` by preserving the browser-generated multipart boundary.
- Prevents the model picker from offering image models that have no compatible configured account for the selected group and channel.
- Keeps text-to-image, image-to-image, and image-plus-text generation aligned with the same account mapping and scheduling rules used by the actual Images API request.

## Fork Changes

- Removes Axios's default JSON `Content-Type` only when the outgoing request body is a real `FormData` instance, allowing the browser to generate the required multipart boundary. Existing JSON requests are unchanged.
- Validates requested, channel-mapped, and upstream billing-model candidates against persistent schedulable account configuration before exposing them in Image Playground.
- Applies channel mapping before account mapping for OpenAI API-key accounts, matching the forwarding path used by image requests.
- Validates OpenAI OAuth candidates after channel mapping and validates Grok API-key and OAuth candidates through each account's effective model mapping.
- Rejects a candidate when its final mapped value is not a supported image model or when account/channel eligibility cannot be verified.
- Uses a dedicated Images API request context so image endpoint model resolution does not affect text requests or Responses API image-tool behavior.

## Upstream Changes

- Baseline remains upstream `v0.1.169` at `682c4fe0e61b851508fa976ac693e0f68a0639eb`.
- No additional upstream commits are included after `v0.1.169-ts.4`; this release contains TokenSupply Image Playground upload and account-eligibility fixes.

## Configuration And Migrations

- No database migration, new environment variable, or new application setting is added.
- Existing image storage, retention, feature flag, group, model, API-key, and channel settings remain compatible.
- Old and new application versions can coexist during blue-green deployment because no shared-data format changes are included.

## Known Limitations

- The picker verifies configured account compatibility, not moment-to-moment capacity. Temporary rate limits, overload, or all compatible accounts being concurrently occupied can still cause submission-time unavailability.
- OpenAI OAuth accounts with only unrelated non-empty text-model mappings may hide an otherwise usable default image model. This fails closed and does not expose a model that is known to be unusable.
- Image Playground still depends on Redis and the configured private object store for retained asynchronous results; this release does not change storage or retention behavior.
- Generated images remain downloadable only through authenticated owner-scoped Image Playground endpoints. No public object URL is introduced.
