# TokenSupply v0.1.171-ts.1

## Highlights

- Adds pre-update PostgreSQL and host-configuration backups to the managed deployer, bounds automatic backup retention to the newest two completed backups, and keeps the current plus two previous application images available for rollback.
- Updates the upstream baseline to `0.1.171`, including Tencent and Aliyun captcha providers, unified Codex outbound identity and version synchronization, safer refunds, serialized subscription renewal, and multiple gateway reliability fixes.

## Fork Changes

- Creates a PostgreSQL custom-format dump before a managed application update and copies the application, Compose, deployer, Nginx, image-state, and optional private-registry configuration into the same private backup directory.
- Writes a manifest and SHA-256 checksums, verifies the completed backup, and blocks the update before pulling or changing an application container when backup creation fails.
- Keeps the two newest completed automatic backups. Operator-owned files under the separate `manual` directory are never enumerated or removed by automatic cleanup.
- Keeps the current application image and two previous managed versions. The immediately previous stopped container remains directly restartable; the second previous immutable image can recreate the inactive slot without registry access.
- Runs backup and image cleanup only after health checks, traffic handoff, draining, activation, and deployment persistence complete. Cleanup warnings are recorded on the successful job, while maintenance remains serialized against another update.
- Keeps database recovery separate from application rollback. Managed rollback never restores an older database automatically, avoiding loss of orders, users, or usage written after an update.

## Upstream Changes

- Baseline: upstream `v0.1.170` (`7e2e9ba05026b7126318aa0754c1afa0ac00bc58`) -> upstream `v0.1.171` (`f0e7a9c7a23a7d02fb159b62fa809621eb0475a6`), synchronized through upstream `00b8596176809906993169c283671811ad04f58d`.
- Adds Tencent Captcha and Aliyun Captcha 2.0 alongside Turnstile, using one mutually exclusive provider selection in administrator security settings. When Tencent or Aliyun is selected, OAuth starts and Passkey login are also included in captcha enforcement; the existing Turnstile coverage is unchanged.
- Normalizes Codex outbound identity and derives User-Agent and version headers from one effective version. Official Codex version synchronization runs periodically with startup debounce and a smaller release API request.
- Extends reasoning-effort policy to composite groups, adds cached OpenAI reset-credit details, updates the pinned Grok CLI identity, and aligns Claude OAuth authorization with the Claude Code endpoint.
- Fixes Codex load-shed errors incorrectly cooling accounts, usage records being dropped on billing failure, concurrent subscription renewals losing time, concurrent token refresh races, temporary Messages account failover, terminal WebSocket events on lease loss, and several account recovery and pricing-display issues.
- Makes insufficient-balance refunds require explicit administrator force confirmation and makes Stripe refund retries idempotent. Direct integrations with the administrator refund API must handle the `require_force` response.

## Configuration And Migrations

- No database migrations are added between `v0.1.170-ts.2` and this release.
- The deployer supports backup root, PostgreSQL service, application config, Docker config, deployer binary, and backup timeout settings. Existing installations receive documented defaults from the managed installer; see `docs/MANAGED_UPDATE_RETENTION.md`.
- Upstream adds `gateway.disable_codex_originator_normalization`, defaulting to `false`. Leave it disabled unless a later upstream load-shed policy requires opting out of identity normalization.
- Tencent and Aliyun captcha are optional and configured from administrator security settings. Tencent CSP requirements are injected automatically. Sites with a custom CSP that enable Aliyun must allow `https://*.alicdn.com` in `script-src` and `style-src`, as documented in `deploy/config.example.yaml`.
- Existing Turnstile and Passkey behavior remains configured as before unless the captcha provider or related settings are changed.

## Deployment And Rollback

- Publish only through the controlled Promote Release workflow after this Release PR and the merged `main` SHA pass all required gates. Deploy production separately through the administrator update page after the immutable image, digest, checksums, and completion ledger are available.
- A managed application update upgrades the host deployer only after successful traffic handoff. Therefore, the first update from an older deployer still uses the previous backup behavior; the new automatic backup and retention contract applies from the following application update.
- To require the new backup before the first application update, install the matching host-only deployer bundle first. This does not stop or recreate the running application, but it must be treated as a separate controlled host change.
- Monitor backup duration and free disk space before updating, then health, traffic handoff, deployer maintenance warnings, and retained backup/image counts after completion.
- Image rollback to `v0.1.170-ts.2` remains database-compatible because this release adds no migrations. Application rollback never rewinds PostgreSQL; restoring a backup requires an explicit disaster-recovery procedure with writers stopped.

## Known Limitations

- The first managed application update from an older deployer does not automatically use the new pre-update backup path unless the matching host deployer bundle is installed first.
- Backup time and disk usage scale with the live PostgreSQL database and configuration size. A backup or checksum failure safely blocks the update, but operators must resolve capacity or permission errors before retrying.
- Automatic database backups are disaster-recovery artifacts, not application rollback points. Database restore remains manual by design.
- Tencent captcha requirements are injected into custom CSP policies automatically. Aliyun `https://*.alicdn.com` requirements are not injected, so administrators enabling Aliyun with a custom CSP must update `script-src` and `style-src` themselves.
- Direct refund API integrations must handle upstream `require_force` behavior for insufficient user balance.
