# TokenSupply v0.1.172-ts.2

## Highlights

- Returns a clear `404 model_not_found` response when a model is disabled by the channel pricing list instead of reporting a retryable `503` platform failure.
- Excludes channel model restrictions and insufficient user balance from platform availability while retaining their audit records.
- Shows the final outcome, responsible party, error category, and platform-availability inclusion in the administrator error detail view.

## Fork Changes

- Adds a typed channel-model restriction error so persistent pricing configuration rejections remain distinct from temporary account capacity failures.
- Propagates the typed restriction through Responses, Chat Completions, Embeddings, Images, Count Tokens, and OpenAI-compatible, Anthropic, Gemini, and Grok handler paths.
- Classifies the channel restriction as `client_rejected / client_policy` with `counts_toward_sla=false`.
- Recognizes `Insufficient account balance`, `insufficient_balance`, and `insufficient_account_balance` as `business_limited / user_quota` with `counts_toward_sla=false`.
- Preserves generic no-account diagnosis and `503` behavior for transient cooldown, rate-limit, and account-capacity failures.

## Upstream Changes

- Baseline remains upstream `v0.1.172` at `155c49496026e86c17637614f5452cc7486db10c`; this fork revision contains no additional upstream synchronization.

## Configuration And Migrations

- No database migration is included.
- No environment variable, administrator setting, pricing rule, model allow-list, or billing calculation changes.
- The existing `ignore_insufficient_balance_errors` setting is unchanged. When disabled, insufficient-balance audit rows remain stored but are excluded from platform availability.
- `v0.1.172-ts.1` and `v0.1.172-ts.2` remain compatible during managed blue-green deployment.

## Known Limitations

- The direct typed rejection covers the reported channel pricing precheck. A channel using `billing_model_source=upstream` can still return generic no-account behavior when all accounts are filtered later for account-specific reasons.
- Historical rows keep their original raw status and message. The production correction for the confirmed Luna, GPT-5.4-mini, and insufficient-balance rows is an operational data repair, not a migration in this release.
