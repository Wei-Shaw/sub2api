# TokenSupply v0.1.173-ts.2

## Highlights

- Makes asynchronous image-generation failures visible in the user workspace, administrator image-task view, operations errors, and user error records, with the complete stored or normalized failure reason preserved.
- Adds first-class Antigravity channel monitoring for both Claude/Anthropic and Gemini protocols without requiring administrators to hand-build the dedicated route.
- Keeps content-policy rejections out of provider SLA failures while preserving them as clear user-visible safety errors.

## Fork Changes

- PR #82 records image-generation failures from upstream providers, object storage, and final task-state persistence in the shared operations pipeline. User and administrator task views now show the stored failure reason instead of a generic failed state; safety errors remain normalized and operations details remain subject to the existing log-size limit.
- Grok and OpenAI content-policy rejections use a stable safety classification and remain excluded from platform availability. The existing success path, authorization boundaries, and prompt privacy are unchanged.
- PR #83 allows an Antigravity group Key to be selected for either an Anthropic or Gemini monitor. The UI stores an origin plus a managed `/antigravity` suffix, and probes resolve to `/antigravity/v1/messages` or `/antigravity/v1beta/models/...` as appropriate.
- Create and update operations validate the provider/path combination while retaining HTTPS, public-host, DNS-rebinding, query, fragment, and arbitrary-path protections.
- Editing a monitor and changing its provider requires a new Key even after a provider round trip. Selecting a local Antigravity Key restores the dedicated route automatically; external upstream Keys can still be entered directly.

## Upstream Changes

- No upstream commit is added in this patch release. The upstream `0.1.173` baseline and all upstream behavior documented for `v0.1.173-ts.1` remain unchanged.

## Configuration And Migrations

- No database migration is included.
- No new environment variable or administrator setting is required.
- Existing non-Antigravity channel monitors retain origin-only endpoint behavior.
- Existing Antigravity account mixed-scheduling settings are unchanged. The explicit `/antigravity` monitor route forces the Antigravity platform and does not depend on mixed scheduling.

## Deployment And Rollback

- Publish only through the controlled Promote Release workflow after this Release PR and the exact merged `main` SHA pass Backend CI, complete Release Preflight, immutable-candidate verification, and final release audit.
- Production deployment remains a separate managed blue-green update after the tag, GitHub Release, image digest, checksums, and completion ledger are available.
- Image-only rollback to `v0.1.173-ts.1` is schema-compatible because this release adds no migration or required configuration.
- An Antigravity monitor created by `ts.2` continues to run, list, toggle, and delete after rollback, but the `ts.1` edit form rejects its `/antigravity` endpoint. Re-upgrade to `ts.2` to edit it, or delete and recreate it using a configuration accepted by the older version.
- After deployment, verify one failed image task is visible to its user and administrators, and run both a Claude and Gemini monitor using an Antigravity group Key.

## Known Limitations

- Redis image-task state and the operations error record are separate writes. A process exit in the narrow interval between them can still omit one operations record even though the task failure remains available through its primary state store.
- The monitor form can infer the Antigravity route only when a local group Key is selected through the Key picker. A manually entered Key is intentionally treated as an external upstream Key because the browser has no trustworthy group identity for arbitrary text.
- External provider behavior was not replayed against every live account during release preparation. Automated tests cover both Antigravity protocol paths without using production credentials.
