# TokenSupply v0.1.173-ts.3

## Highlights

- Fixes Antigravity Gemini channel probes returning `400 INVALID_ARGUMENT` by emitting the explicit `user` role required by the upstream native Gemini route.

## Fork Changes

- Gemini monitor challenge bodies now include `contents[0].role = "user"`, matching the established Antigravity account-test request format.
- Adds a regression test that parses the generated request body and requires the explicit role.

## Upstream Changes

- No upstream commit is added. The upstream `0.1.173` baseline remains unchanged.

## Configuration And Migrations

- No database migration or configuration change is required.
- Existing monitor definitions remain compatible.

## Deployment And Rollback

- This emergency patch is schema-compatible with `v0.1.173-ts.2` and can use the normal managed blue-green update.
- Image-only rollback to `v0.1.173-ts.2` remains available, but Antigravity Gemini native probes will again return `400` there.

## Verification

- A production read-only investigation reproduced the failure with the generated request body. The same request returned `200` after adding only `role: user`; model resolution remained `gemini-3.6-flash-tiered`.
- On `root@agent.local`, the focused channel-monitor regression tests and a complete backend server build passed. No compilation or tests ran on the local workstation.
- Per the operator's emergency authorization, this patch skips the normal independent audit and full local release matrix; repository CI and immutable release promotion remain required.

## Known Limitations

- No new known limitation is introduced by this request-format hotfix.
