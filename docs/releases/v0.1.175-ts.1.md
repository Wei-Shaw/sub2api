# TokenSupply v0.1.175-ts.1

## Highlights

- 改善 Gemini / Antigravity 渠道探针的挑战请求兼容性，给 Gemini 留出足够的内部思考预算，避免正常响应被误判为挑战失败。
- 追上游 `v0.1.175`，同步近期 OpenAI Responses、图片生成错误处理、TTFT、服务档位计价和 Codex OAuth 稳定性改进。

## Fork Changes

- Gemini 探针的 `generationConfig.maxOutputTokens` 从通用的 50 调整为专用的 256；Gemini 因思考预算耗尽而未返回完整挑战文本时，错误信息会明确说明是预算截断。
- 增加回归测试，验证 Gemini 探针请求包含正确的用户角色和专用输出预算。
- 账号编辑页重新构建并带上自动停调阈值的中英文翻译，避免旧前端 bundle 显示原始 i18n key。
- 账号统计的 LiteLLM/fallback 路径改用统一计费明细，补齐图片输入、图片输出回退和 5m/1h 缓存价格；通用 Gateway 同步完整传递缓存创建分档，避免 1h 缓存被误按 5m 价格统计。

## Upstream Changes

- Baseline: `upstream/v0.1.173` -> `upstream/v0.1.175`。
- 同步 Codex OAuth 设备指纹收敛，减少不必要的设备和会话变化。
- 同步 OpenAI Responses 的嵌套 usage、可见 TTFT、空完成事件 failover、无效字段处理及请求项 ID 兼容修复。
- 同步图片生成 OAuth 流错误、Grok usage、服务档位账号成本和运维显示等修复。

## Configuration And Migrations

- 不需要数据库迁移。
- 不新增必须配置的环境变量或设置。
- 现有渠道、分组、监控和服务档位配置保持兼容。

## Deployment And Rollback

- 使用正常的蓝绿部署流程即可，无需停机维护。
- 从 `v0.1.175-ts.1` 回滚到此前生产版本时，数据库与配置保持兼容；回滚后 Gemini 探针会恢复旧的 50 token 挑战预算行为。
- 发布前必须确认候选镜像、bundle、版本号和 commit SHA 完全一致；正式 tag 只能由 `Promote Release` workflow 创建。

- 已通过账号统计真实调用链回归，验证 5m/1h 缓存创建 token 从上游 usage 一直传递到 LiteLLM/fallback 成本结果。

## Known Limitations

- 本地环境不替代 GitHub Actions 的完整 Release Preflight；在 `Backend CI` 和 `Release Preflight` 对同一 release commit 全部成功前，不创建正式 tag。
- P2：OAuth 图片请求 `n>1` 当前串行拆分为多次上游请求，延迟和上游调用量随图片数线性增加；本版不改变该既有行为。
- P2：Codex OAuth 默认收敛账号级设备/会话指纹；共享账号若依赖上游按 session 限额，需要继续观察兼容性。
