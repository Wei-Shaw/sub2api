# TokenSupply v0.1.179-ts.1

## Highlights

- Channel model catalogs now provide a clearer, channel-owned model shelf for API users and administrators.
- Groups can redirect requests blocked by prompt auditing to a designated fallback group when that policy is configured.
- This release also brings in the upstream 0.1.179 baseline, including adaptive account protocol routing, broader provider support, and channel-monitor improvements.

## Fork Changes

- Adds the fork-owned model catalog and price book. Restricted channels advertise their configured, priced models through `/v1/models`; new channels default to restricting their storefront to those models.
- Adds `fallback_group_id_on_prompt_audit_block` to groups. When prompt audit blocks a request, the configured compatible fallback group can be selected before returning an error.
- Stabilizes the group usage rollup integration tests by making their Shanghai-date expectations independent of the CI runner's UTC session timezone.

## Upstream Changes

- Baseline: `upstream/v0.1.177` -> `upstream/v0.1.179`.
- Adds adaptive API protocol routing and related account capability handling.
- Extends channel monitoring with quota modes and supports Kimi, Zhipu, and DeepSeek across relevant channel and composite-routing flows.
- Adds channel-pricing service-tier and interval multipliers, along with reliability fixes for OpenAI, Grok, Gemini, proxy probing, and monitoring workflows.

## Configuration And Migrations

- New migrations:
  - `243_add_usage_log_effective_model_indexes_notx.sql`: concurrent indexes for effective requested and upstream model lookups. It must run outside a transaction; the managed migration runner handles this.
  - `244_channel_monitor_quota_mode.sql`: channel-monitor quota modes, account linkage, provider coverage, quota snapshots, and the default-off `channel_monitor_show_quota` public setting. The rollout uses additive nullable columns, compatibility triggers, and reviewed constraints so mixed-version writes remain safe.
  - `245_composite_routes_add_cn_providers.sql`: allows Kimi, Zhipu, and DeepSeek as composite route targets.
  - `246_channel_pricing_multipliers.sql`: nullable service-tier and interval price multipliers with restart-safe, positive-value constraints.
  - `247_add_group_prompt_audit_fallback.sql`: optional prompt-audit fallback group reference with compatibility enforcement for the hard-delete path.
  - `248_channel_monitor_account_id_index_notx.sql` and `249_group_prompt_audit_fallback_index_notx.sql`: concurrent indexes that run outside a transaction through the managed migration runner.
- The schema changes are additive and nullable where appropriate. The previous completed image remains suitable for application rollback after migrations have run.

## Deployment And Rollback

- Use the managed deployer blue-green flow; do not apply these migrations manually or edit production files directly.
- Take and verify a database backup before deployment. Ensure the managed migration runner can execute migration 243 outside a transaction.
- The previous completed version is `v0.1.177-ts.3`. Rolling back restores its application behavior but does not remove the new schema, indexes, catalog storefront behavior, or prompt-audit fallback configuration.
- Formal tags must be created only through `Promote Release` after the exact merged `main` SHA passes all required gates and receives the final release audit.

## Known Limitations

- Prompt-audit fallback requires an explicitly configured, compatible fallback group. When no eligible fallback exists, the request remains blocked.
- Restricted channels with no priced catalog entries intentionally expose an empty storefront instead of falling back to the full platform catalog.
- `channel_monitor_show_quota` remains off by default; administrators must enable it before quota snapshots are exposed publicly.
