# TokenSupply v0.1.179-ts.2

## Highlights

- Account model capability lists now come from the account's actual upstream model response, so newly enabled upstream models can appear without adding another static frontend model-list patch.
- Channel administrators can continue to choose the public storefront, while the channel picker shows how many bound accounts have each model according to their latest upstream capability snapshots.

## Fork Changes

- Account capability probes continue to refresh `extra.upstream_model_snapshot` on the existing background schedule. The account editor and model selector now read that same snapshot instead of mixing in the frontend's curated model list.
- Manual refresh fetches and persists the same upstream snapshot, returns its server-side synchronization time, and reports an error if persistence fails. It does not add identity mappings or otherwise change account model mappings.
- Antigravity account editing now shows the latest upstream-supported model IDs and synchronization time separately from request-to-upstream model mappings. This prevents a successful capability probe from silently rewriting administrator mapping policy.
- Channel catalog coverage remains an account-by-account count from upstream snapshots, for example `1/3`, rather than an all-account intersection or a static list inference.

## Upstream Changes

- Baseline unchanged: `upstream/v0.1.179`.
- This is a TokenSupply fork revision focused on consistent account capability visibility and routing evidence.

## Configuration And Migrations

- No new configuration or database migrations.
- Existing `extra.upstream_model_snapshot` data remains the single account-capability record. Accounts with no successful snapshot remain eligible under the existing fail-open scheduling rule so a probe failure cannot empty a pool.

## Deployment And Rollback

- Deploy only through the managed deployer blue-green flow after the release workflow completes and its completion ledger matches the immutable image digest.
- The previous completed version, `v0.1.179-ts.1`, remains rollback-compatible. No schema changes are introduced by this release.

## Known Limitations

- Capability snapshots are only as recent as the last successful probe. The background service refreshes stale or never-synced eligible accounts in bounded batches; manual refresh is available when an immediate check is needed.
- Channel coverage is an availability indicator, not a promise that an account is currently free of rate limits, quota limits, or other scheduling constraints.
