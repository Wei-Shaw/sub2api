# TokenSupply v0.1.179-ts.3

## Highlights

- Antigravity Pro and Ultra account capability sync now queries the same `daily` endpoint used by their request traffic. Gemini 3.7 Flash is therefore recorded when the account's upstream response supports it.
- Account test and scheduling-panel model lists now show the account's synchronized upstream capability snapshot instead of a static catalog.
- The channel model picker clearly distinguishes Antigravity Gemini reasoning variants as High, Medium, Low, and Tiered.

## Fork Changes

- The Antigravity model probe targets the account's effective forwarding endpoint. It no longer accepts an earlier successful response from a different fallback endpoint as the account capability record.
- An unsynchronized Antigravity account returns an empty administrator model list rather than implying support from a curated static list. Existing scheduling remains fail-open for unsynchronized accounts; after a successful sync, snapshot capabilities participate in the existing account eligibility checks and channel coverage count.
- Gemini thinking-tier labels are only added for Gemini model variants in the Antigravity storefront. The stored channel model IDs, pricing cards, and routing mappings are unchanged.

## Upstream Changes

- Baseline unchanged: `upstream/v0.1.179`.
- This fork revision contains the Antigravity account-capability consistency fixes merged in PR #118.

## Configuration And Migrations

- No new configuration, environment variables, or database migrations.
- Existing `extra.upstream_model_snapshot` remains the sole persisted account-capability record. Use the account refresh action to synchronize an existing account immediately; scheduled refresh continues to update it afterward.

## Deployment And Rollback

- Deploy only through the managed blue-green deployer after the release workflow publishes the immutable image and completion ledger.
- The previous completed version, `v0.1.179-ts.2`, remains rollback-compatible because this release introduces no schema or configuration migration.

## Verification

- The merged `main` commit `138a9af8fa2609cfb6bc27a19fa810b2f1d885ff` passed Backend CI and Release Preflight push workflows before this Release PR was prepared.
- The Release PR must pass its own exact-head Release Preflight, including full frontend release validation, candidate build, migration history, module tidy, and release/deployer contract checks.

## Known Limitations

- The account model list is as current as the last successful upstream sync. A failed or never-run sync does not claim static support in the administrator UI, while the existing scheduler fail-open rule avoids emptying an account pool solely because a probe is unavailable.
- Channel coverage indicates synchronized capability, not instantaneous availability. Rate limits, quota, cooldown, and account status can still prevent dispatch at request time.
