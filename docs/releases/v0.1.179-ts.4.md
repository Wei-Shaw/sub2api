# TokenSupply v0.1.179-ts.4

## Highlights

- Antigravity 账号会自动使用最近一次成功探测到的新模型，不需要再手工把模型加入账号白名单。
- 渠道继续负责公开模型、上游映射和定价；账号探测快照只用于确认该账号实际支持哪些上游模型。

## Fork Changes

- 当请求模型已经出现在 `extra.upstream_model_snapshot` 中时，Antigravity 调度和账号测试不再因旧账号缺少 `model_mapping` 条目而返回 `not in whitelist`。
- 保留旧账号映射作为历史兼容兜底，但新探测模型优先按快照直接透传；快照存在时仍会检查模型覆盖范围，避免把请求分配给未探测到该模型的账号。

## Upstream Changes

- Baseline: `upstream/v0.1.179`。
- 本次 fork revision 修复 Antigravity 账号模型快照与旧账号白名单语义冲突的问题。

## Configuration And Migrations

- No new configuration, environment variables, or database migrations.
- 现有 `extra.upstream_model_snapshot` 继续作为账号能力探测记录；不需要手工回填账号 `model_mapping`。

## Deployment And Rollback

- 按 managed blue-green deployer 发布，并以 Release workflow 生成的不可变镜像和 completion ledger 为准。
- 本版本无数据库迁移，上一完成版本 `v0.1.179-ts.3` 保持可回滚。

## Verification

- `cd backend && go test -tags=unit ./internal/service -count=1` 通过。
- `cd backend && go test -tags=unit ./internal/... -count=1` 通过。
- Release Preflight、完整 CI、候选镜像构建和线上部署需由该 release commit 对应的 GitHub Actions 完成。

## Known Limitations

- 账号能力以最近一次成功探测为准；探测快照为空时，现有 fail-open 行为仍保留，避免探测故障导致整个账号池被误清空。
- 渠道映射必须先把公开模型映射到上游实际模型；账号快照不会替代渠道定价或公开模型配置。
