# TokenSupply v0.1.182-ts.1

## Highlights

- 增加 Kiro 平台能力，包括 OAuth、缓存模拟、会话粘性、endpoint 模式、额度统计和渠道监控支持。
- 增加本地插件安装与运行时支持，并加强插件包签名、路径和沙箱安全校验。
- 同步上游 `v0.1.182`，包含 OpenAI Responses Lite 并行工具调用修复、支付完成后的余额刷新等改动。

## Fork Changes

- 修复 Kiro token 刷新、事件流、usage 统计、缓存计费和强制刷新场景。
- 支持 Kiro 独立的缓存创建/读取模拟比例、自动会话粘性和渠道监控分组聚合。
- 修复平台配额、渠道监控 provider、composite route 中遗漏 Kiro 导致的数据库约束失败。
- 修复发布迁移的回滚兼容性：已有大表索引改为并发创建，数据回填和约束变更显式拆分并纳入发布门禁审计。

## Upstream Changes

- Baseline: `upstream/v0.1.179` -> `upstream/v0.1.182`。
- 重点同步 OpenAI Responses Lite 并行 tool call、Kimi 路由、Anthropic cache TTL、支付结果余额刷新和 OAuth 相关修复。

## Configuration And Migrations

- 新增 Kiro 分组配置：缓存模拟模式及比例、自动粘性、粘性 TTL、endpoint 模式。
- 新增插件安装、插件绑定、插件制品和渠道监控分组绑定相关迁移。
- 迁移包含 Kiro 平台配额/provider/组合路由约束修复；升级前请确认数据库账号具备 DDL 权限。
- 新增索引使用 `CREATE INDEX CONCURRENTLY`，由 `_notx.sql` 迁移单独执行。

## Deployment And Rollback

- 按 managed blue-green deployer 和 Release workflow 生成的不可变镜像部署。
- 本版本迁移通过 managed deployment 回滚兼容性门禁；发布前的上一完成版本仍可作为镜像回滚目标。
- 生产环境升级后不要修改已执行的迁移文件；后续数据库变更必须新增迁移。

## Verification

- Backend CI、Security Scan、Release Preflight 全部通过。
- 后端 unit/integration 全量测试、`go vet`、`govulncheck`、迁移门禁和发布安全测试通过。
- 前端 lint、280 个 Vitest 文件共 1925 个测试、生产构建全部通过。

## Known Limitations

- `gosec` 全仓仍报告仓库既存告警，未发现本版本新增的安全问题。
- 前端测试和构建仍会输出少量既存 Vue/i18n/Vite warning，不影响通过结果。
