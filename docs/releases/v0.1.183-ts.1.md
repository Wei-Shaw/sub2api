# TokenSupply v0.1.183-ts.1

## Highlights

- 同步上游 `v0.1.183`：Codex 路由模型目录（按组模型列表与能力同步）、OpenAI OAuth 账号 429 配额耗尽暂停调度、错误响应记录实际上游 endpoint。
- 补齐 Kiro 移植审计 6 项缺口：profileArn 统一解析、Responses compaction、namespace 自定义工具、监控表单分组数据源等。
- 修复 Grok 长上下文（≥200K）少计费与渠道监控 v2 错误聚合 SQL 语法错误导致监控停更的问题。

## Fork Changes

- Kiro 平台（PR #132）：profileArn 统一解析（凭据真实 ARN > Social ARN > Builder ID 占位符回退），Q/KRS 请求与用量查询统一走解析结果；Responses compaction（`compaction_trigger`/`compaction_summary` 输入项、摘要封装与下一轮 replay）与 namespace 自定义工具身份还原；渠道监控表单改为账号/分组二选一数据源并移植 Antigravity 固定路由；前端分组平台入口补齐 Kiro。
- Grok 长上下文计费（PR #133）：xAI Grok 整单输入（input + cache_creation + cache_read）达到 200K（含边界）时整单按长上下文单价计费（输入 ×2 / 输出 ×2）。此前远程目录条目不带长上下文字段导致规则失效、≥200K 请求按基础单价少计费；现由运行时从本地价卡回填规则，对已带完整规则的目录条目幂等。
- 渠道监控（PR #134）：修复错误聚合 SQL 单参数 `NULLIF` 语法错误（8/25 18:34 起监控数据停更），composite 分组错误按账号具体平台聚合，新增真库集成回归测试。
- 上游同步（PR #135）：合入上游 37 个 commit，解决 12 个冲突文件（含 VERSION）；保留渠道 storefront 约束、PR #122 渠道映射先于账号模型支持检查、Kiro 分组平台等 fork 语义；合并后测试修复 2 处（UseKeyModal 补 kiro 条目、邮箱换绑测试装配 EmailQueueService）。

## Upstream Changes

- Baseline: `upstream/v0.1.182` -> `upstream/efb46db0a`（v0.1.183 及之后的修复）。
- Codex 路由模型目录：按组暴露路由模型清单与能力同步，含 API-key 目录缓存隔离、DeepSeek Codex 默认值、不可调度账号能力交集处理、session-id 会话亲和、WSv2 过期 tool ID 清理、恢复 tool-call item ID 类型保持。

- kimi 并发 403 恢复为可恢复；antigravity 兼容模式 token 上限 clamp；composite 精确账号模型别名路由。
- auth：邮箱换绑增加别名去重与并发守卫（他人邮箱的 Gmail +alias/点号变体换绑返回 409）。
- channel-monitor-v2：上游独立修复了同一 NULLIF bug，与 fork PR #134 一致。
