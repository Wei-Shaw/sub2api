# TokenSupply v0.1.183-ts.2

## Highlights

- 用户并发限制错误分类修复：用户自身在途请求超过并发配额、网关本地返回 429 时，不再被记作 provider 限流（此前计入平台 SLA 错误统计），改归客户端 `user_concurrency` / `business_limited`，不计 SLA。

## Fork Changes

- Ops 错误分类（PR #137）：`ClassifyOpsError` 新增网关用户槽位本地并发限制（`concurrency limit exceeded for user`）早退分支，与账号池容量分支对称。根因：本地 429 被同时写入 `upstream_status_code`，`isOpsUpstreamEvidence()` 因 `upstreamStatus > 0` 误判"有上游证据"，行被归为 `provider_rate_limit`（provider 责任、计入 SLA），永远到不了既有的 `user_concurrency` 分支。新增回归用例，输入镜像生产数据（本地 429 + 陈旧 upstream 429 + phase=request + rate_limit_error）。账号槽位并发限制（`concurrency limit exceeded for account`）仍归平台容量，行为不变。

## Upstream Changes

- 无。上游基线与 v0.1.183-ts.1 相同（`upstream/v0.1.183`，efb46db0a），本版本未合入新的上游 commit。

## Configuration And Migrations

- 无。本版本无数据库迁移、无新增配置项与环境变量。

- 无迁移变更，回滚到上一完成版本 `v0.1.183-ts.1` 完全兼容。
