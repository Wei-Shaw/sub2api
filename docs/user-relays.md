# 用户私有中转站与公共共享

在用户菜单打开「我的中转站」。首次打开会准备一个默认私有组合分组。接入上游后，在「API 密钥」页面创建绑定私有组的调用密钥，使用本站原有 API 地址调用。

## 使用规则

| 调用入口 | 本站扣费 | 提供者收益 |
| --- | --- | --- |
| 本人的私有组 | 0 | 0 |
| 公共余额组，选中别人提供的账号 | 按公共组价格 | 实际提供者获得分成 |
| 公共余额组，选中本人提供的账号 | 按公共组价格 | 本人同样获得分成 |

私有组仅所有者可用，只接受所有者的账号。免费表示本站不扣消费余额，也不消耗本站的付费配额；上游额度、上游费用、账号并发及请求限流仍然生效。私有组不能自动回退到收费组，也不能作为其他组的回退目标。

公共组由 Admin 维护。用户可以把同一账号接入私有组和多个兼容的公共组，也可以取消公共组勾选停止共享。私用与共享共用账号的并发和上游额度。当前支持向按余额计费的公开组提供账号；订阅组、其他用户的私有组和平台专属组不接受用户上架。

共享不会向消费者返回上游凭证。消费者请求经过提供者配置的上游；提供者在本站面板看到自己的用量、账号状态和收益，不会得到消费者身份或请求正文。

## 凭证与分组

- API Key：选择平台，填写上游 API Key。官方地址可以留空，外部中转站填写公网 HTTP(S) 地址。
- OAuth：选择 OAuth 并导入 `access_token`，可同时导入 `refresh_token`、`expires_at` 和平台所需的组织、项目等信息。复用原有的自动刷新逻辑。本页不提供交互式 OAuth 授权向导。
- 高级 JSON：支持 `model_mapping`、`api_base_urls`、`account_mode`、`upstream_protocol` 等凭证字段。更新时未提交的原有凭证会保留。
- 用户不能设置平台代理、账单倍率、其他人的资源归属等管理员字段。
- 上游地址拒绝私网、回环地址、URL 中的用户名密码等；用户账号的转发限制公共地址并禁用凭证跨重定向传播。
- 删除资源停止后续分配，历史收益保留。删除私有组后，仍绑定该组的密钥会因分组已删除而拒绝请求。

## 收益与结算

金额沿用本站现有的 USD 计价单位。Admin 在公共组设置「提供者分成比例」，默认 `0.9`，即消费 1 USD 时提供者获得 0.9 USD 站内余额。

扣费、收益流水和余额入账在同一个数据库事务内完成，使用原有请求幂等键。重复处理不会重复扣费或重复赚钱。收益可以在站内继续消费，没有提现接口。长请求按确认的实际用量结算，页面每 10 秒刷新收益。

现有请求后扣费允许余额透支。发生透支时，提供者收益先记为待结算，不立即转成消费余额。消费者补足欠费后，提供者刷新收益（包括面板自动刷新）会原子结算待入账收入。两人的钱包按用户 ID 顺序加锁，处理双方互相调用和自己调用自己的情况。

用户账号的普通调用结算在请求处理线程内执行，避免收入进入可丢弃的内存用量队列；异步批量任务保存分组、提供者和分成快照，并在捕获预付冻结余额的事务中分成。

## 部署与验证

先部署包含 `243_user_relays.sql` 的后端，使账号归属、私有组约束和收益表迁移完成，再部署同版本前端。多实例部署应先完成全部后端升级，再开放新入口，保证账号归属与收益结算使用同一版本。既有平台账号和分组的所有者为空，其使用权限及收费规则保持兼容。认证缓存版本升级后旧快照会重新加载。

开发验证：

```bash
cd backend
go test -tags=unit ./internal/service ./internal/repository ./internal/server/middleware ./internal/handler ./internal/util/urlvalidator -run 'Relay|UsageBilling|BatchImage'
go test -tags=integration ./internal/repository -run '^TestRelay' -count=1
```

集成测试启动独立 PostgreSQL、Redis 容器，覆盖所有权隔离、零余额私用、自用分成、去重、事务回滚、双向并发、欠费后结算和批量任务分成。前端用例位于 `frontend/src/views/user/__tests__/RelayView.spec.ts`。
