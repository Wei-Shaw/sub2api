## Why

个人 API Key 当前只能绑定一个分组。当主分组暂时没有可用账号或不支持请求模型时，请求会直接失败，即使用户还有其他可用分组。为提升可用性，需要允许每把个人 API Key 配置一个有明确优先级的备用分组列表。

## What Changes

- 个人 API Key 创建和编辑接口新增有序的备用分组 ID 列表。
- 用户只能选择自己有权使用、与主分组平台相同的启用分组；主分组不能重复出现在备用列表中，备用列表内也不能重复。
- 请求选路先尝试主分组；主分组因计费资格不可用或无法选出支持目标模型的可用账号时，严格按配置顺序尝试同平台备用分组，支持该平台内按量与订阅分组之间切换，不允许跨平台切换。
- 请求一旦选中某个分组，该请求的账号选择、模型映射、定价、用户分组倍率、限流、用量日志与错误上下文均使用实际选中的分组。
- 不对已经发送到上游的普通失败响应执行跨分组重放，避免非幂等请求重复执行。
- API Key 认证缓存和更新失效逻辑携带备用分组配置，保证修改后及时生效。
- 个人控制台提供可排序的备用分组选择控件，并在列表中展示配置摘要。
- 企业 API Key 保持现有组织订阅绑定语义，不开放个人备用分组配置。

## Capabilities

### New Capabilities
- `api-key-fallback-groups`: 定义个人 API Key 的有序备用分组配置、校验、选路与实际分组计费语义。

### Modified Capabilities

无。

## Impact

- 数据库：`api_keys` 增加有序备用分组 ID 的 JSON 字段及迁移。
- 后端：API Key schema/domain/repository/cache、用户 API、网关认证上下文及各协议账号选择入口。
- 前端：个人 API Key 类型、创建/编辑表单、列表展示、国际化和组件测试。
- 兼容性：未配置备用分组的现有 API Key 行为不变；现有 `group_id` 仍是主分组。
