## Why

当前系统可以记录用户 token 消费、账号调用成本和支付订单，但自动计算的上游调用成本不够准确，不能作为成本中心的经营成本。管理员无法按时间范围准确回答现金收入、付费消费收入、赠送消耗、人工录入的账号及运营支出和最终利润之间的关系，也无法持续记录账号续费等后续成本。

现在建立成本中心，可以让新发生的收入和支出从产生时就留下可审计的 USD 快照，并把现金流和已实现经营利润分开展示，避免充值与 token 消费重复计算收入。

## What Changes

- 新增统一的成本中心流水能力，支持收入、支出、赠送消耗、套餐权益和利润口径。
- 新增账号支出流水，支持创建账号时录入初始支出、批量对每个账号分别追加支出、从账号操作菜单或成本中心选择账号追加支出；成本中心也可不关联账号追加全局手工支出，支持“审计账号支出”分类和可选备注。
- 新增一次性和周期性支出计划；周期性计划生成待确认记录，确认后进入现金支出。
- 新增全局运营支出，覆盖代理、服务器、数据库、带宽、支付手续费、返佣、退款损失及其他费用。
- 新增充值订单、套餐订单、充值赠送和套餐使用的成本中心快照；充值赠送在余额充值订单完成时按实际赠送金额记为已结算支出，不迁移或重算历史数据。
- 成本中心不再自动记录或展示上游调用成本；账号成本统一由管理员通过账号一次性或周期性支出补录，历史自动上游成本流水保留审计但从报表排除。
- 成本中心流水展示可读的成本来源人和调用所用账号；用量调用成本展示所用账号名称。
- 新增套餐按时间窗口内 token 额度使用比例确认已实现收入的规则，并单独展示未实现余额和过期权益。
- 新增成本中心管理端页面，支持 USD 汇总、经营利润/现金利润、时间范围筛选、分类和对象维度明细及导出所需的查询接口。

## Capabilities

### New Capabilities

- `cost-center`: 统一记录新发生的收入、支出、赠送消耗和套餐收入分摊，并按时间范围生成现金流和经营利润报表。

## Impact

- Backend: 新增成本中心、支出计划/流水、套餐收入分摊的数据表、服务、查询 API 和权限控制；在账号创建/批量编辑/账号操作、支付履约和 token 计费路径写入快照。
- Frontend: 新增管理员成本中心页面、汇总卡片、时间范围筛选、收入/支出明细、支出录入与周期计划界面，并扩展账号相关表单和操作菜单。
- Billing: 现有用户扣费和上游成本计算继续服务于用量与运维数据，但成本中心不采用自动上游成本；新增 balance source、订单、套餐和赠送快照用于分类，不改变既有扣费金额。
- Data: 统一金额保存为 USD，并保留原币种、汇率和来源快照；历史记录不回填、不迁移。
- Operations: 新增成本中心读写权限、审计日志和周期支出待确认流程。
