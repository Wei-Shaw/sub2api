起点：production a60a604ebc019218805fa0f85f43ec4421f1de73（实际线上 18219）。

范围：Grok `/videos/generations` 新任务。创建前冻结原用户、密钥、分组、订阅、账号、模型、时长、分辨率和费用，成功接收任务 ID 后先落库再响应。后台 GET 确认成功后通过现有 SQL 原子结算；客户端查询/下载复用同一租约和结算门。任务结束不依赖客户继续查询。编辑/延长和其他供应商保留原计费流程。

历史 tracking_only 任务不晋升、不批量补扣；管理监控继续只读。只有已明确授权的两条历史欠费此前已补扣，不能重复执行。

## 发布与回退限制

`GATEWAY_GROK_VIDEO_DURABLE_SETTLEMENT_ENABLED` 默认 false，仅控制新任务登记，不停止已登记任务的结算。

1. 候选使用独立数据库/模拟上游验证。连接生产数据库的候选必须保持新登记开关关闭，不发付费测试请求。
2. 先切兼容代码（开关关闭），等待旧 Nginx 在途请求结束，核实全部旧应用连接无流量后停止旧应用工作器。不可让旧工作器继续抢占新的 Grok 结算任务。
3. 再通过蓝绿部署启用开关。未确认旧工作器退出前不得启用。
4. 回退应使用同一修复镜像且关闭新登记；已有任务继续由兼容工作器完成。存在未结算 Grok durable 任务时禁止退回不兼容旧镜像或停止最后一个兼容工作器。
5. 禁止恢复旧数据库覆盖在线数据；不修改价格、用户倍率或余额。源码包仅由已审核 tag 的 git archive 生成。
