# 视频任务只读监控修复

用户明确要求此模块只用于分析和监控视频进度及情况。费用严格按现有使用记录关联展示，不允许监控流程发起扣费、补扣、退款或重新提交生成。

## 实现

- 为 tracking_only 记录增加独立后台 GET 查询，先按任务 ID、用户、API 密钥和上游账号完整关联 usage_logs；已存在使用记录则同步完成状态，不再请求上游。
- 上游完成仅更新任务记录；没有使用记录时费用显示待核查，不新增使用记录或改余额。原 Grok / Ark 查询结算与 OpenAI 持久化结算流程保留。
- 独立租约和 30 秒间隔，查询失败退避至最多四分钟；超过一天且至少十次仍未确认则暂停并显示待核对。404、结果过期及超时不当作生成失败。已完成快照的结算重试不受此暂停限制。
- 暂停旧任务的后台重试不封死客户端查询：原任务归属客户端仍可每四分钟显式复查一次，保留上游恢复后的原有取回与结算流程；监控页本身不会触发该流程。
- 原生状态、已取消/失败，以及上游账号线路指纹检查均有回归测试。监控只 GET 状态，不下载视频、不接触生成接口。
- 无任务 ID 的 submission_unknown 保留待核对，不能安全猜测关联，也不自动重提。
- 新旧容器共享数据库时，tracking_only 的 next_attempt_at 继续保持远期值，旧工作器也不能领取监控记录。
- 四条当日已通过原上游 GET 验证的旧 Grok 记录，通过精确任务 ID、用户及账号约束补入路由指纹；不批量重绑定其他历史账号。

## 验证与发布

执行后端构建、全量 unit、视频专项 race；前端类型、lint、全量测试；409 项定制守卫及六项守卫测试。独立 PostgreSQL 检查并发租约、身份错配、已扣/未扣记录同步、余额及使用记录数量不变，以及旧工作器隔离。

按 production 标签归档构建，候选端口 18197，保留 18196 回退。发布操作脚本 video-monitor-deploy.py；精确历史路由补齐脚本 video-monitor-activate.py。

不新增数据库迁移。回退只恢复应用流量和价格监控连接，不覆盖数据库，也不恢复或补写使用记录。停止自动查询的任务保留待核对；需要恢复时应先验证上游结果，不能直接重新生成。
