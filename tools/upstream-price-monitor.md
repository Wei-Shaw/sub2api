# 上游价格监控

管理端路径：`/admin/channels/upstream-price-monitor`

该功能不保存上游登录态，也不复制 API Key。它直接使用已有生产账号的凭据，读取：

- `GET /v1/usage`：按生产 Key 和模型聚合的真实 Token 与 `actual_cost`。
- `GET /v1/sub2api/billing`：Key 倍率、峰时倍率和计费时区。
- `https://api.x5m5x.com/pricing/`：按次三档声明价。

## 工作方式

1. 对每个配置的生产账号和模型保存远端累计账本与本地 `usage_logs.id` 高水位。
2. 按 `COALESCE(upstream_model, model)` 汇总本地请求。
3. 只有请求数、输入、输出、缓存写、缓存读五项都与远端差值一致时，才保存可信样本。
4. 累积多个满秩时间窗后，求解输入/输出/缓存写/缓存读单价。秩不足时仅显示 pending，不猜测价格。
5. 渠道建议价是实测成本 × 1.20；展示官方基础价不变，只修改三位小数倍率。

历史观察只在配置的有效期内复用，并按账本日期、有效凭据和计费上下文隔离。近共线样本会被视为秩不足，不会用不稳定解自动改价。

账本日期固定为 Asia/Shanghai 当天，跨日时只重建 baseline，不将滚动窗口清退误判为降价。倍率、峰时或 service tier 在窗口内混合时，该样本不参与自动定价。

## 模型目录与探测范围

- 管理端可单独执行“免费扫描上游模型”：只读取所选生产 Key 的 `/v1/models`，不发付费请求。
- 新模型首次出现时为 `discovered`，必须所有选定账号的完整快照都可见，管理员才能改为 `managed` 并开始探价。
- 账号模型快照任一行异常、空列表、重复 ID 或任一账号请求失败，整轮都不累计下线次数，也不允许用陈旧覆盖率纳管新模型。
- 已纳管模型只有在连续 3 轮完整快照且距最后出现已超过 24 小时时，才进入 `suspected_retired` 并暂停付费探测。
- `ignored` 和 `retired` 都是可恢复状态。移出探测范围只停止价格监控，不会删除账号映射、渠道定价、展示价或历史证据。
- `managed` 只表示“纳入价格探测”，不会自动将模型发布给用户。新模型要自动 apply，还必须先建立单模型渠道定价行，并在展示定价中填入可核验的官方基础价；系统不会伪造新模型官价。
- 每个 run 都固定模型目录 revision；无论手动还是自动 apply，目录发生任何新扫描或范围变更后，旧快照都会被拒绝。

## 安全上线

- 迁移默认 `enabled=false` 且 `mode=observe`。
- 先在控制台选择生产账号和目标渠道，保持观察模式至少 24 小时。
- 若同一上游 Key 还被站外程序使用，本地与远端计数将无法闭合，自动应用必须保持关闭。
- 手动运行总是 dry-run；应用需再次提交 `run_id + snapshot_hash`。
- 应用使用单个 PostgreSQL 事务，并保存渠道价和展示倍率的回滚快照。
- 快照同时固定目标渠道、舍入精度和配置版本；过期、乱序或在运行期间被关闭的自动价格应用会被拒绝。
- 只有真实数值变化才会写表和刷新缓存；无变化运行记录为 no-op，不覆盖上一个可回滚快照。
- 回滚同时校验“应用后值”；如果管理员在应用后又手动改过价格，整个回滚会 fail-closed，不覆盖后续人工修改。
- 已完成且无可用回滚的运行记录保留 90 天；删除 run 时通过外键级联清理对应样本，最新真实回滚快照不受影响。
- Token 普通上下文的基础 interval 与渠道行同步；已配置的 interval multiplier 和长上下文档保留。
- 共享多模型定价行会 fail-closed，需先拆成单模型行；按次渠道需要精确的 0/256K/512K 三档区间。

## 当前边界

- Token 自动对账仅纳管内置的 18 个国模。
- 按次不发付费探针，使用报价页显式三档价格。
- 主动补探默认关闭。开启后，仅对当轮缺少可信自然样本的模型使用同一生产 Key 发送付费请求。
- 主动模式要求周期不少于 15 分钟，多生产账号可并行；模型起点按持久化 run ID 轮转，即使单轮超时也不会让列表尾部模型永久饥饿。
- 每个主动样本都校验 `/v1/usage` 请求数差值必须等于 1，且同模型本地用户流量必须为 0。出现重叠时样本作废，并将远端/本地高水位同步重建，避免污染下一个被动窗口。
- 每次发送前先将 `active_probe_pending` 持久化，扣费后每个样本立即清除并前移 checkpoint。进程崩溃或超时后，下轮会在宽限期后先重建账本再做被动对账。
- 账本出现 `+1` 后还会连续重读直到计数/成本稳定，再复查本地流量。探针只在实时负载和等待队列均为 0 时，原子占满该账号的全部有限并发槽，结算 checkpoint 后立即释放。无限并发账号无法建立排他租约，不会主动补探。
- 主动模式每个缺证模型会使用输入、输出和两次稳定长前缀样本，可观测到缓存写/读时一并求解。当前未设费用上限，启用前应确认上游额度策略。
- 不可观测的缓存字段保持原价，不写入 0。
- 同一上游 Key 不能在纳管列表中重复绑定多个本地账号；配置会直接拒绝这种情况。
- 多个不同生产 Key 的 Token 价格只在每个 Key 都得到可信证据时应用；各计费维度取最高实际成本再上浮 20%，保证路由到任一纳管 Key 都不会吃掉利润。
- 渠道价缓存失效目前是进程内的。单进程 OVH 部署可直接使用；多副本部署在接入 Redis/版本广播前，不应开启自动应用。
